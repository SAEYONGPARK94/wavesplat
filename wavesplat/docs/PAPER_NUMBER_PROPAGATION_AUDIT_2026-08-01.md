## 0. 한 줄 결론

**이것은 텍스트 편집 작업이 아니라 재실행 작업이다.** 헤드라인 표는 이미 측정된 데이터로
새 계산 없이 교체 가능하지만, 논문의 나머지 표들은 전부 위상수정 이전 실행에서 나왔다.
헤드라인만 고치면 논문은 **현재의 "일관되게 낡은" 상태에서 "앞뒤가 안 맞는" 상태로 악화된다.**

## 4. 권고 — 3단계

**1단계 (즉시, 무위험) — ✅ 2026-08-01 실행 완료**: 메인 5-지표 표 + 헤드라인 +
LETKF 문장을 §2 값으로 교체하고, 동시에 절제·적응형-N·raydrop 표에
**잠정 표시(provenance note)**를 달았다 — "이 표는 트래커 수정 이전 실행에서 산출됨,
재실행 예정". 부분 편집이 불일치가 아니라 **공개된 부채**가 되도록 하는 방식이며,
이 프로젝트가 이미 쓰는 규약이다
(`tmp/rerun_2026-07-25/CARRIED_TABLES_FINEMESH_2026-07-25.md`의 carried-over 규약).

실제 수정 지점 (37 insertions / 25 deletions):
- 초록·기여목록·결론: 0.199 → 0.115, 40.1% → 65.5%
- LETKF 비교 문장: 0.199 → 0.115 (vs 0.228 유지)
- `tab:fivemetric` WaveSplat 행: 0.115 / 0.916 / 0.764 / +0.538 / 0.173
- `tab:strong_baseline` WaveSplat 행: 0.115 / 0.916 / 0.764 / +0.538 / **+0.381** / 0.102 / 14.5
  (Dir R² 부호 반전으로 LETKF 행의 볼드 해제 — 최고값이 WaveSplat으로 이동)
- `tab:strong_baseline` 캡션의 SS 부트스트랩 CI: [+0.06,+0.28] → **[+0.42,+0.65]**
  (post-fix 에피소드별 SS 중앙값 100개, 10k 재표본, seed 20260801)
- 산포 서술: `0.199 ± 0.085` → `0.115 ± 0.116`
- 메시 논의(L1873): 0.199 → 0.115
- 해상상태별 표(`tab:bybf`): BF2 0.145→**0.029**, BF3 0.138→**0.016**,
  BF4 0.222→**0.150**, BF5 0.271→**0.238**, Avg 0.199→**0.115**
  (희소 해상이 사실상 해결됨이 표에 드러남)
- 12-에피소드 부분집합 문단: "40.1% 대비 더 큰 마진" 설명 삭제(전제가 사라짐) +
  provenance 각주 신설
- `tab:ablation`·`tab:sparsity` 캡션에 provenance 문장 추가

⚠ **타이밍은 의도적으로 손대지 않았다.** 배치 환경 측정치는 위상수정으로 8.27→7.02 ms로
빨라지지만(−15%), 논문의 11.0/14.5 ms는 다른 측정 환경에서 carried-over된 값이고
`CARRIED_TABLES` 규약이 "환경이 달라 대체하면 측정 프로토콜 변경을 메시 갱신으로 위장하게
된다"고 명시한다. 즉 현재 논문 타이밍은 **보수적**(실제보다 느리게 적음)이다.

**2단계**: 절제·적응형-N·raydrop을 수정된 기본값으로 재실행. 베이스라인은 재사용.
⛔ 재실행 시 `init_method` 명시 필수(W9 오염 사고 재발 방지).

**3단계**: 추적 한계 절(L2170–2213)과 VR/SS 귀속 서술을 다시 쓴다. 수정 후 VR 0.916,
SS +0.538이므로 "진폭 감쇠가 장기 예보를 갉아먹는다"는 서사의 근거가 약해졌다.

## 5. 별도로 발견된 무결성 항목 (전파 범위 밖이지만 기록)

`paper/wavesplat.tex`에 **"Bergamasco" 및 "stereo" 출현 0회.** 제출본은 100% 합성이다.
실측 자산(bank-MMSE 이식, 롤링 refit, GT-free 인터록)이 논문에 전혀 반영돼 있지 않다.
이는 수치 전파와 별개의 결정 사항이며, 2026-08-01 페르소나 토론에서 OE 리뷰어 페르소나가
"선점 여부가 아니라 이것이 진짜 블로커"라고 지목했다.

또한 논문의 13.4 ms 지연 수치는 **추적 단계만** 측정한 값이다. 롤링 refit을 운용에 넣으면
`fit_wall_s_m3`가 0.78–1.52 s(R\*=2 s)이므로 지연 표는 불완전해진다.
