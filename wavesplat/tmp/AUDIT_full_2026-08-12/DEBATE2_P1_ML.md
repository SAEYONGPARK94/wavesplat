## 4. ★★★Q1-#4 상세 — A 배치에서 감사 셋이 다 놓친 것

### 4.1 인용된 PRIMARY 우위는 **선택기의 값이 아니라 λ 의 값**이다

PRO 재설계의 PRIMARY = `SELECT{AUTO-L1, V2K} − RESTART{AUTO, AUTO-SEED-NULL}`.
팔의 λ 를 코드에서 확인하면:

- `AUTO-L1` → `run_s9.py:71` `L1_TREAT = 1e-4`
- `V2K` → `run_x2.py:27` `EXTRA['V2K'] = {'lambda_l1': M.L1_TREAT}` = **1e-4** (기록된 cfg 로 재확인)
- `AUTO`, `AUTO-SEED-NULL` → `run_s9.py:78-96` `L1_SHIP = 1e-3`

⟹ **SELECT 는 처치 팔 두 개, RESTART 는 무처치 팔 두 개다.** 내 재도출:

| 비교 | 희소 | 혼잡 |
|---|---|---|
| `SELECT{AUTO-L1,V2K} − RESTART{AUTO,SEED-NULL}` (λ 교락) | **55/9, p=3.5e-09** | 24/8, p=0.0070 |
| 순수 λ `AUTO-L1 − AUTO` (S9 PRIMARY) | 50/14, p=7.1e-06 | 27/5, p=1.1e-04 |
| **λ 맞춘 대리** `SELECT{AUTO,AUTO-NT} − RESTART{AUTO,SEED-NULL}` | **12/26, p=0.0336 (선택이 진다)** | **2/13, p=0.0074 (선택이 진다)** |

⚠**대리팔의 한계를 명시한다**: `AUTO-NT` 는 `V2K` 가 아니고, 희소에서 `AUTO` 를 **63/1** 로 압도한다
⟹ "두 팔이 대등할 때의 선택" 을 재는 대리로는 **불완전**하다. 그래서 나는 이것을 **"선택이 진다"의
증거가 아니라 "교락을 빼면 부호가 보장되지 않는다"의 증거**로만 쓴다.
**λ 맞춘 진짜 비교는 오늘의 자료로 계산 불가능하다** — `AUTO-L1` 의 두 번째 시드-삼중이 없기 때문이다.
**그 사실 자체가 A 배치가 무엇을 담아야 하는지를 결정한다.**

### 4.2 혼잡 팔은 **런 전에 죽었다**

두 팔 모두 λ=1e-4 인 **완전히 맞춘** 비교:

- `V2K − AUTO-L1` **혼잡 0/32** (AUTO-L1 이 **32 에피소드 전부 승**, p=4.657e-10)
- ⟹ **전지오라클 선택기 vs 항상-AUTO-L1 = 0개선 / 0악화 / 32동점 = +0.00%**

**한 방법이 다른 방법을 완전 지배하면 선택기의 상한은 정의상 0 이다.** 혼잡에서 방법선택은
검정력의 문제가 아니라 **질문이 없는 문제**다. (참고: 실제 GT-free 선택기는 1 에피소드에서
엉뚱한 팔을 골라 **+5.64%** 손해를 본다 — 즉 혼잡의 기대값은 **0 이하**다.)

희소는 반대다: `V2K − AUTO-L1` **33/31, p=0.9007** = 진짜 동전던지기이고,
전지오라클 **33개선/0악화/31동점**, 실제 선택기 **25/2/tie37, 적중 54/64**.
⟹ **A 는 희소 전용 배치로 축소되어야 한다.**

### 4.3 그래서 A-v2 는 이렇게 써야 한다 (사전등록 골격)

| 항목 | 사양 |
|---|---|
| **블록** | **희소만.** 신선 에피소드 N (혼잡 제거로 같은 GPU 시간에 희소 n 을 **두 배**로) |
| **셀** | `AUTO-L1` **시드 삼중 2개**(A, A′) + `V2K` 시드 삼중 1개 + `AUTO-DUP` = 에피소드당 **10런** |
| **PRIMARY (하나)** | `SELECT{AUTO-L1, V2K}` − `RESTART{AUTO-L1, AUTO-L1′}` (짝 부호검정, 양측). **두 절차 모두 2런 = 계산량 일치**, **두 절차 모두 λ=1e-4 = 처치 일치** |
| **선택 통계량** | **`window_resid` 하나로 동결**(S11 이 `all_resid` 와 갈렸다 — 둘 다 보고하되 PRIMARY 는 하나) |
| **⛔사전 금지** | ⛔`RESTART{…} − AUTO`(1런 대 2런) 를 배포 주장으로 승격 금지 — **최선-of-2 대 1 은 구조적으로 유리**하다. ⛔혼잡 결과를 PRIMARY 로 승격 금지(상한 0.00%, §4.2) |
| **분할 임의성** | ⛔S9 의 6시드를 3/3 으로 **재분할해서 쓰지 않는다**. 신선 시드로 A, A′ 를 **처음부터 두 삼중으로 생성**하면 B-5 가 소멸한다 |

4. ⚠**무효화되지 *않는* 것을 같이 못 박는다**: 레짐 내부 비교(λ, 추적기 on/off, k 품질, 선택기)는
   **모든 팔이 같은 기하 위에 있으므로 짝 대조로서 유효**하다. B3 은 **외부 타당도**를 죽이지
   **내부 타당도를 죽이지 않는다.** ⟹ K7-v2 도 A-v2 도 이 발견으로 무효가 되지 않는다.

## 9. Q6 — 재발 방지 규칙 **하나**

> ## ★**"정정은 인용 지점이 아니라 *패턴*으로 등록한다 — 그리고 그 패턴은 기계가 전수 검색한다."**
>
> `reference_citation_bans.md` 의 **모든 항목에 기계 검색 가능한 `pattern` 을 붙이고**,
> `memory/*.md` + `CLAUDE.md` + `tmp/*/RESULT.md`·`DECISION.md` 를 전수 grep 하는 검사를 둔다.
> **ban 파일 자신을 제외한 어디에서든 패턴이 발견되면 실패**한다.
> ⟹ **정정을 "등록"하는 유일한 방법이 ban 항목 추가가 되므로, ban 파일이 다시는 뒤처질 수 없다.**

**왜 이것인가.** A2 의 구조는 *"규율을 지키는 세션일수록 거짓을 읽는다"* 였다.
원인은 정정이 **사람이 옮겨야 하는 정보**였다는 것이다. 이 규칙은 정정을 **실패하는 검사**로 바꾼다.

**오늘 이것이 실제로 잡았을 것들** (전부 실존):
`"λ.*미배포"` → `MEMORY.md:25`, `project_s9_prereg:31` ·
`"init_method: v2_konly"`(출하 기본값 문맥) → `CLAUDE.md:53` ·
`"132.6"` → `CLAUDE.md:49` · `"~?2배"`(bank-MMSE 문맥) → `MEMORY.md:95`,
`project_bankmmse_port:41` · `"57 tests"` → `CLAUDE.md:46` · `"6.2 m"`(LJ Grid2 문맥) →
오늘의 프로브 헤드라인.

**구현 = 30줄 미만, 런 0회.** 오탐은 **ban 항목이 문맥 정규식을 갖도록** 강제해 억제한다
(예: `"2배"` 가 아니라 `"bank[^\n]{0,40}2배"`). 오탐이 나면 **패턴을 좁히는 것이 곧 정정 문장을
정밀하게 만드는 일**이므로 비용이 헛되지 않는다.

**부수 효과 하나 — 같이 채택할 것**: 배포 상태 수치(λ·`init_method`·테스트 개수·파일 개수)는
**손으로 적지 않는다.** `tools/shipped_state.py` 가 코드에서 읽어 생성한 블록만 문서에 존재하고,
검사가 그 블록의 신선도를 본다. 오늘 `CLAUDE.md` 의 **5개 오류가 전부 이 한 조치로 소멸**한다.
