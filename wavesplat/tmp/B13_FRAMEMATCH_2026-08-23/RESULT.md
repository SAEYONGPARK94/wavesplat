# B-13 결과 — **프레임 불일치는 재발하지 않았다** (2026-08-23 심야)

## 배경
`b1_full_comparison.json` 의 옛 헤드라인을 죽인 **1순위 사유**는 정확도가 아니라
***"두 팔이 같은 프레임에서 채점된 적이 없다"*** 였다(WS 120–220 vs ETKF 301, 100/100 전건).
그리고 지금 논문이 인용하는 `B-1`(혼잡 **62/64 · −38.58%**)은
- `SHIP` = `W16`(08-22) · 기준선 = `S16`(08-14) = **8일 떨어진 두 배치**
- ⛔**두 결과 파일 모두 프레임 수를 기록하지 않는다**
⟹ B2 심사가 *"`B-1` 은 프레임 정합을 스스로 증언하지 못한다"* 고 지적했다. **옳은 지적이다.**

## 측정
혼잡 에피소드 1개(`BF4_15comp_seed0`)를 **지금 코드로** 두 팔에 각각 한 번 돌렸다.

| | 채점 프레임 | 창 시작 | avg nRMSE | 벽시계 |
|---|---|---|---|---|
| `SHIP`(배포) | **160** | (초기화 이후) | 0.0766 | 7.5 s |
| `SPEC25` | ⛔러너가 반환 안 함 | — | 0.2059 | 47.1 s |

사전등록 규칙으로는 **`FRAMES-UNKNOWN`** 이다(한쪽이 수를 안 내놓는다).

## 보충 도출 (⚠사전등록 판정이 아니다)
에피소드에서 직접 재도출:
```

```
⟹ ★***두 팔의 채점 창이 프레임 수와 시작 시각에서 모두 일치한다.***

## 판정
✅**옛 결함은 재발하지 않았다.** `B-1` 헤드라인에 프레임 불일치 단서를 붙일 필요가 없다.
⚠**단서 셋**:
1. **표본 1**(에피소드 하나). *"전 에피소드에서 정합한다"* 로 쓰지 마라.
2. 사전등록 규칙으로는 **`UNKNOWN`** 이고 `MATCH` 는 **보충 도출**이다.
3. ⛔**계측 결함은 그대로다** — 두 러너 모두 프레임 수를 결과 행에 싣지 않는다
   (`RMSE_near`·`avg_shell_rmse`·`loss_history` 에 이은 같은 부류의 **네 번째**).
   ⟹ ★**처방: 채점 창을 결과 행에 실어라**(`n_frames_scored`·`t_first`·`t_last`).
   그러면 다음 배치는 이 검증을 **런 없이** 할 수 있다.
