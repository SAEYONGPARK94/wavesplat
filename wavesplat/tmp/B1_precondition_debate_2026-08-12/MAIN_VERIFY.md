## V-1. **`direction1` 은 출하 시스템이 아니다** — ✅**P4 확인, 결정적**

`scripts/d74_closed_loop_trajectory.py:36-41, 67-85`:

```
L_FOOT = 20.0          # per-step LiDAR footprint patch size [m]
M_STEP = 30            # observations per step
T_OBS  = 20.0          # observation window [s]   (DT_STEP=0.5 → K=40 스텝)
SIGMA  = 0.02

```

⟹ **LiDAR 광선 캐스팅·차폐·raydrop·입사각·사거리 제한이 전부 없다.** 관측은

**출하 파이프라인과 대조** (`wavesim/pipeline.py` → `generate_rays`, 측정: `data_s9_crowded_2026-08-11`):

### ★결론 — 메인 세션의 08-12 오후 "정정"이 **과잉정정이었다**

메인 세션은 `traj_step1b_relax.json` 의 **오라클 21/24** 와 `platform_aperture.json` 의
**CRB CONFIRMED** 를 근거로 *"이동이 이길 경로는 열려 있다"* 고 사용자에게 보고했다. 그러나:

1. 그 21/24 는 **정지 기준선이 20×20 m** 인 비교다. **출하 정지 팔은 이미 149–203 m** 다.
2. ★**direction1 에서 *이긴* 이동 팔(112–116 m)조차 출하의 *정지* 팔(149–203 m)보다 작다.**
3. **⟹ "이동이 개구를 벌어준다"는 이 자료로 출하 구성에 전이되지 않는다.**
4. ★★★**비대칭**: 메인 세션은 **출하 팔에서 잰 K6**(완벽한 k = 가치 0, p=0.79)를
   **토이에서 잰 direction1** 로 기각했다. **방향이 거꾸로다.** S1(08-08)의 교훈이
   *"출하 팔에서도 재라"* 인데 정확히 반대로 적용했다.

### 그래도 남는 것 (⛔여기서 또 과잉정정하지 말 것)
- 이것은 **"이동이 도움 안 된다"의 증거가 아니다.** direction1 이 전이 불가라는 뜻이다.
- **출하 구성에서 플랫폼 이동을 잰 배치는 존재하지 않는다** ⟹ 진짜로 **미측정**이다.
- ⟹ B-1 의 정당화는 살아남지만, **메인 세션이 인용한 근거는 죽는다.**
  사전등록은 **출하 생성기 + 출하 추정기**여야 한다(P4 조건 ③).
