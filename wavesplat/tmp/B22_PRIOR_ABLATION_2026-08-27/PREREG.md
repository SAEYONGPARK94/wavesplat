## 2. ★설계 문제 — 교락이 **넷**이고, 위원장의 2×2 는 **코드에 존재하지 않는다**

배포된 두 경로는 팔이 아니라 **패키지**이고 넷이 동시에 다르다(전부 코드에서 확인):

| | 학습 경로(배포 기본) | 해석적 경로 |
|---|---|---|
| 제안원 | 확산 사전 `propose_atoms` | v2 빔포밍 `initialize_from_frames_v2` |
| VARPRO | **400**(`sequential_update.py:913-917`) | ⛔**구조적으로 없음** |
| 결합적합 반복 | `learned_init_iters=0` | 코스투파인 **900** = `[200,200,500]` |
| 앙상블 | k=1 (라우터가 learned 면 **앙상블을 안 만든다**, `:1924` 조건절) | **k=3** median-of-3 |

### 2.1 ⛔**`ANA+VP` 는 만들 수 없다** (런 전 실측)
`grep -n apply_varpro wavesplat/**/*.py` = **2행**뿐이고 호출 지점은 `sequential_update.py:917`
= `_initialize_learned` **안**이다. ⟹ 해석적 라우팅에서는 VARPRO 가 **호출되지 않는다.**
위원장의 2×2 `{제안원}×{VARPRO}` 중 `ANA+VP` 칸을 라우팅으로 만들려면 **`wavesplat/**` 을
고쳐야 하고**, 그러면 *"배포된 적도 측정된 적도 없는 제3의 팔"* 이 된다(저장소가 반복해서
물린 부류). ⟹ **다른 방식으로 가른다.**

### 2.2 ★해법 — 개입을 **"라우팅" 이 아니라 "원자 배열" 로** 옮긴다
`config['learned_atoms']`(dict{kx,ky,energy})는 **이미 노출된 배포 노브**다:
라우터 자신이 `_auto_select_init`(`:1032`)에서 제안 원자를 그 키에 캐시하고
`learned_init_params`(`learned_init.py:346`)가 그것을 읽는다(`propose_atoms` 독스트링 축자:
*"Selection/dedup happens later in pool_and_select so the inline and cached paths are
byte-identical"*).

⟹ **그 배열에 해석적 제안원의 원자를 넣으면**:
파이프라인은 **배포 그대로**(VARPRO 400 · `learned_init_iters=0` · 앙상블 k=1 ·
`ls_fit_wphi` · 가지치기/성장 · 추적기 · 라우팅 `learned`)이고
★**바뀌는 것은 원자의 출처 하나뿐이다.**

| 교락 | 어떻게 죽였나 |
|---|---|
| VARPRO | **짝짓기** — 두 팔 다 `varpro_steps=400`(그리고 S-2 에서 둘 다 0) |
| `learned_init_iters` 900↔0 | **짝짓기** — 두 팔 다 학습 경로이므로 **둘 다 0** |
| `analytic_ensemble_k` 3↔1 | **짝짓기** — 두 팔 다 라우팅이 `learned` 이므로 **둘 다 k=1** |
| **제안원** | ★**남긴다 = 이 배치가 재는 것** |

이것은 `B-16` 이 배포 파이프라인을 그대로 두고 **파수 연속성 하나만** 없앤 것과 같은 형태다.

### 2.3 ⚠그러나 그 팔은 **해석적 제안원에게 가혹할 수 있다**
v2 제안은 원래 **900 반복이 뒤따르도록** 설계됐다(그 반복이 (w,φ)와 k 를 다듬는다).
학습 파이프라인에 꽂으면 그 벌충이 없다. ⟹ ⛔그것만으로 결론을 내면
**W13/W14 의 *"약해진 비교자"* 사고를 세 번째로 반복**하게 된다.
⟹ ★**패키지 수준 대조를 같은 배치에 넣는다**: `ANA-SHIP` = `W15` 의 `ALL-ANALYTIC`
(`auto_switch_thresh=999999` ⟹ v2_konly 라우팅 + **앙상블 k=3** + 900 반복).
`gates_w15.ARMS['ALL-ANALYTIC']` 에서 **import** 한다(손복사 0).

★**두 수준이 괄호를 이룬다**:

| | 무엇이 좋은가 | 무엇이 나쁜가 |
|---|---|---|
| **L1**(`LEARN` vs `ANA`/`ANA-N`) | 노브 **하나**, 교락 3개 소거 | 비교자가 자기 하류를 못 받는다 |
| **L2**(`SHIP` vs `ANA-SHIP`) | 두 패키지 **각자 최선** | 교락 4개 |

⟹ ★**둘 다 통과해야 제목이 산다**(§6). 어느 한쪽만으로는 사지 못하고,
**어느 쪽이 통과하고 어느 쪽이 안 되는지가 그 자체로 답**이다(§6 결정표).

### 3.1 해석적 원자의 정의 (결과 전 고정)
- `initialize_from_frames_v2(frames, n, depth, x_range, y_range, seed=est_seed)` —
  **배포 해석적 경로가 쓰는 바로 그 함수**(빔포밍 coarse → 그리디 peak → refine →
  선형 투영). 새 코드 0줄.
- **energy = w²**. 학습 쪽 energy 는 `denorm_atoms` 의 `a = A²`(`learned_init.py:159` 축자)
  이므로 **같은 양**이다.
- **패딩 제거**: peak 가 모자라면 `initializer.py:578-583` 이 **난수 (kx,ky)** 와 `PAD_W`
  진폭으로 채운다. 그대로 주입하면 비교자에 난수 원자를 심는 셈이다 ⟹ 진폭이 `PAD_W`
  (`initializer.PAD_W` 를 **import**)와 같은 항목을 **버리고 개수를 행에 기록**한다.
  ⟹ ★이 규칙은 **비교자에게 유리한 방향**이다.
- **그리디 접두 성질**: v2 는 잔차를 빼며 peak 를 하나씩 뽑으므로 `n` 을 키워도 앞부분이
  **비트 동일한 접두**다(§10.1 에서 30개의 앞 18개가 18개 요청 결과와 `array_equal` 확인).
  ⟹ **한 번 뽑아 `ANA`(전체)와 `ANA-N`(앞 n_L)이 나눠 쓴다** = 계산 절약 + 중복 구현 0.
- `ANA` 는 **배포 pooling 규칙 그대로**(`energy_thresh=0.03`), `ANA-N` 은 `0.0` 이다.
  ⚠**후자는 노브가 하나 더 다르다** — 그 대가로 **개수 교락**을 없앤다. 그래서 **둘 다 돌리고
  둘 다 통과해야** 한다(§6). 어느 하나를 고르지 않는다.

## 6. 판정 (결과 전 확정 · `gates_b22` 가 `math.comb` 로 계산)

문턱은 `thresholds(n)` 이 **n 에서 직접** 낸다(형제 규약: `NOMINAL` = p≤0.05 최소 ·
`CONFIRM` = p≤가족단위 α 최소 · `NOT_EARN` = `n − NOMINAL`).
**n=48 → NOMINAL 31 (p=0.0297) · CONFIRM 32 (p=0.0147) · NOT_EARN 17.**
**가족단위 α = 0.05 / 2 = 0.025** — 주장 가족은 둘(PRIMARY · SECONDARY)이고
**음성대조는 게이트이지 주장이 아니다**(`B-15`·`B-16`·`B-19` 규약 상속).

- **PRIMARY = 교집합 검정(IUT)**: `L1a`(LEARN<ANA) ∧ `L1b`(LEARN<ANA-N) ∧ `L2`(SHIP<ANA-SHIP).
  ⛔**셋 다 CONFIRM 이어야** `PRIOR-EARNS` 다. 어느 하나의 통과로 제목을 사지 않는다.
- **SECONDARY = IUT**: `S2a`(LEARN-NOVP<ANA-NOVP) ∧ `S2b`(LEARN-NOVP<ANA-N-NOVP).
- **서술용(주장 아님)**: `VP_LEARN`·`VP_ANA`(VARPRO 가 각 제안원에서 얼마를 하는가) ·
  `SHIP_vs_ANA(-N)`(주입 충실도 민감도).

⚠**표본 손실 규칙(결과 전)**: 라우팅 오염·개입 미발화로 제외되는 에피소드가 생기면
남은 `n_used` 에서 계산하고 문턱을 **다시 낸다**. `n_used < 44` 이면 판정은
**`SAMPLE-LOSS-UNDECIDED`** 다(문턱 재계산으로 결론을 사지 않는다).

## 7. 음성 대조 — 그리고 **왜 둘만 무효화하는가**

`ZERO` = **참 제로필드**. 채점 창(`t > 2·Tp`)에서 `nRMSE(0, gt, Hs_true)` 를 프레임마다
계산해 평균한다(`gates_b19.zero_nrmse` 를 **import** — 중복 구현 0).
⛔**상수 `1.0` 을 쓰지 않는다**(2026-08-23 `ZERO_REF` 결함 부류: 실측 계수 전건 철회).

| 팔 | 미달 시 |
|---|---|
| `SHIP` · `LEARN` | ⛔**PRIMARY 무효** → `ARM-NO-SKILL-HERE` |
| `ANA` · `ANA-N` · `ANA-SHIP` | ⚠**무효가 아니라 라벨 수식어** `COLLAPSE[...]` |
| 나머지 | 측정해 적기만 한다 |

**하드 무효화의 사유**: 절제는 *"작동하는 시스템에서 성질 하나를 빼면 얼마를 잃는가"* 이다.
원 팔이 무기술이면 **뺄 것이 애초에 없다.**
**연성인 사유(결과 전)**: `ANA`/`ANA-N` 은 **우리 팔의 의도된 열화**다. 그것이 무기술로
떨어지는 것은 *개입이 강했다*는 뜻이지 측정이 망가졌다는 뜻이 아니다. 무효화 조건으로 걸면
***효과가 클수록 판정이 무효가 되는 단조 역전 게이트***가 된다(`B-12`·`B-19` 가 결과 전에
고친 결함 부류). ⟹ 대신 **수식어**로 두 문장을 가른다:
- 수식어 없음 ⟹ *"작동하는 두 팔 사이의 차"*
- **`COLLAPSE`** ⟹ *"차가 아니라 기술의 소멸"* ⟹ ⛔**상대 중앙 %를 margin 으로 인용 금지**,
  그리고 L1 의 해석은 ***"해석적 원자는 배포 파이프라인에 드롭인 대체가 아니다"*** 까지로
  좁아진다(⛔*"학습 사전이 해석적 파랑 추정을 이긴다"* 로 넓히지 마라 — 그 문장은 **L2** 가 낸다).

⚠**연성 게이트의 통과 조건은 "문턱을 넘었다" 가 아니라 "실제로 측정됐다" 이다.**
초판은 `True` 로 통과시켰고 **결과 0행에서 여섯 개가 조용히 PASS 했다** — 자가진단이 잡아
런 전에 고쳤다(§10.3).
