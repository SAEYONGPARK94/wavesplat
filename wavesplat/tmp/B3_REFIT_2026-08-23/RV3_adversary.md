# 1. 미래 정보 누수 — ✅ SURVIVES (죽이지 못했다)

## 1.1 채널이 하나뿐임을 먼저 확정했다

`bank` 경로에서 `predict_field` → `_bank_predict_grid`(`sequential_update.py:1054-1065`)가
읽는 상태는 **`self._bank` 하나뿐**이다. `_bank_obs`·`_last_t`·`_bank_last_fit_t` 를 읽지 않는다.
그리고 `self._bank` 에 쓰는 곳은 **`_bank_fit_window`(`:1004-1020`) 단 하나**,
그것을 Phase 2 에서 부르는 곳은 **`_bank_update` 의 `:1046` 단 하나**다.

⟹ ★**`update()` 가 예측을 바꾸는 통로는 재적합 외에 존재하지 않는다.** (이 사실은 §3 에서 다시 쓴다.)

## 1.2 시각 회계 — 줄 단위

| 줄 | 무슨 시각인가 |
|---|---|
| `run_b3.py:57` | 채점 예측 = `t0 + ℓ` |
| `run_b3.py:62-63` | 투입 관측의 원 시각 `tt = t0 + ℓ + t_shift`, 즉 **정확히 그 lead 의 프레임** |
| `run_b3.py:68` | `update(FrameData(t = ℓ + t0))` — 예측과 **같은 시각 라벨** |
| `sequential_update.py:1041-1042` | 창 = `[frame.t − bank_memory_s, frame.t]` ⟹ **`frame.t` 를 포함** |

**질문**: *"lead ℓ 의 예측이 lead ℓ 의 관측을 쓰지 않았음이 보장되는가?"*
**답: 보장된다.** 루프가 `① predict(:57) → ② update(:68)` 순서이므로, lead ℓ 을 채점하는 시점의
`self._bank` 는 **lead ℓ−1 의 `update()` 까지만** 반영한다. 창이 `frame.t` 를 포함하는 것은 맞지만
그 창은 **lead ℓ 채점이 끝난 뒤**에야 만들어진다.

★**정확한 문장**: `REFIT2` 는 매 lead 에서 **최신 관측보다 1 s 앞을**, 최신 *재적합*보다
**1~2 s 앞을** 예측한다(재적합이 짝수 lead 에서만 발화하므로 적합 나이 ∈ {1,2}).
`FROZEN` 은 **ℓ s 앞을** 예측한다.

## 1.3 두 개의 독립 실측으로 보강했다 (원자료 진단, 추정 런 0회)

1. **관측이 실제로 투입됐는가** — `run_b3.py:63` 의 `|P_fut[:,2] − tt| < 1e-6` 술어를
   36 장면 전건에 대해 재평가: **14/14 lead 전부 매칭**(전 36 장면). ⟹ 루프는 진짜 **1 s 갱신**이다.
   ⚠**이것은 `G-2b` 가 못 잡는 것이다**: `refit_calls == 7` 은 *"14회 투입"* 과 *"짝수 lead 7회만 투입"*
   **둘 다와 양립**한다(재적합이 2 s 주기이므로). 내가 밖에서 막았다.
2. **채점 시각 어긋남** — `maps_gt[li] = Zfut[round(ℓ/dt)]` 의 실제 프레임 시각이
   `rec.t[i0] + ℓ` 와 **1e-6 내 일치**(36/36) ⟹ GT 시각 = 예측 시각. 어긋남 없음.
3. **초기화 오염** — `with_future_obs=True` 는 별도 생성기(`default_rng(900+win)`)만 쓰고
   `P`·`z`·`sg` 를 건드리지 않는다(`scene_station.py:134`, 과거는 `700+win`). 오염 0.

## ★1.4 그런데 이것이 §1 의 서술을 무너뜨린다

`RESULT_B3.md §1` 은 **"효과가 lead 와 함께 커진다(−11.6% → −32%)"** 를
*"`C` 가 말한 기제 '유효수명' 과 정합"* · *"'우연히 좋아 보이는 것' 이 아님을 자료가 스스로 증명한다"* 로 읽는다.

⛔**그 추론은 성립하지 않는다.** §1.2 에서 확정했듯 `REFIT2` 의 적합 나이는 **모든 lead 에서 1~2 s 상수**,
`FROZEN` 은 **ℓ 에 선형**이다. ⟹ *적합이 나이를 먹으면 나빠진다* 는 **어떤** 성질이든
정확히 이 모양(lead 와 함께 벌어짐)을 낳는다. **모양은 설계의 서명이지 기제의 판별자가 아니다.**
자료는 *"적합 나이가 오차를 늘린다"* 와 *"재적합이 새 정보를 동화한다"* 와
*"재적합이 수치 드리프트를 리셋한다"* 를 **하나도 가르지 못한다.**

허용 = **"효과가 lead 와 함께 커진다"**(사실). ⛔금지 = **"자료가 기제를 찍는다/증명한다"**.

# 2. 두 팔이 같은 스트림인가 — ✅ SURVIVES (죽이지 못했다)

`_bank_update`(`:1022-1052`)의 본문에서 노브가 가르는 것은 **`:1043-1047` 다섯 줄뿐**이다.

```
:1037-1042   Pf,zf 추출 → _bank_obs 에 vstack → frame.t−40 로 prune   ← 두 팔 동일
:1043-1047   if bank_refit_every_s is not None and ... : _bank_fit_window(*_bank_obs)  ← 여기만 갈린다
:1048-1051   preds = median(bank.render(Pf)) ; loss 반환                ← 두 팔 동일
```

⟹ `FROZEN` 도 **회전 창을 정확히 같은 방식으로 유지하고, 같은 렌더를 돌리고, 같은 loss 를 낸다.**
그리고 `_bank_obs` 를 읽는 곳은 `_bank_fit_window` 호출부 **하나뿐**이다.
⟹ ★**RESULT §2 의 *"받아 놓고 쓰지 않는다"* 는 축자로 참이다.** 실측 보강: 두 팔 모두 `update()` **14회**(§1.3).

## ⚠2.1 다만 처치는 단일요인이 아니다 (WOUND, 소)

`REFIT2` 의 재적합 창은 `[frame.t−40, frame.t]` 이므로 **신규 관측 투입**과
**가장 오래된 관측 퇴출**이 동시에 일어난다. 실측(36 장면, ℓ=14 시점):

| 양 | 값 |
|---|---|
| 초기 `_bank_obs` | **600 점 전건**(`m_cap=600` 이 항상 발화 — 원 자료는 4,800–6,000 점) |
| ℓ=14 시점 창 크기 | 569–573 점 |
| 창 중 **신규 관측 비율** | **29.3–29.5%** |
| ⟹ 초기 40 s 중 퇴출된 몫 | 약 29% |

⟹ 기제 귀속을 하려면 **팽창 창(퇴출 없음) 재적합** 팔이 필요하다. 지금은 못 가른다.

## ✅2.2 내가 의심했던 세 번째 교락은 **발화하지 않는다**

`_bank_fit_window:1010-1013` 은 `len(z) > bank_max_obs(600)` 이면

`len(z)` 가 바뀌면 추출 자체가 바뀌므로 재적합이 *"자료 추가"* 가 아니라 *"자료 교체"* 가 될 위험이 있었다.
**실측: 252 회 재적합(36 장면 × 7) 중 창이 600 을 넘은 경우 0회.** ⟹ 교락 없음. **죽이지 못했다.**

★**설계 처방**: 진짜 음성 대조는 **①②를 뒤집은 팔**(누수 양성 대조)이다. 그것이 `REFIT2` 를

## 6.2 그래도 짝 차이는 깨끗하다

# ★8. 신규 — B-3b 의 사전등록된 누수 판별자가 **유효하지 않다** (결과 전 경고)

`gates_b3b.py` 독스트링이 내 검증을 결과 전에 인용하며 이렇게 배정해 뒀다:

> - **누수 가설이 참이면** — … **1 s 가 가장 좋고 단조**여야 한다.
> - **유효수명 가설이 참이면** — 어느 지점에서 **포화**하고 …

⛔**이 이지선다는 성립하지 않는다.** 재적합 주기 τ 에서 적합 나이는 **[1, τ]** 로 묶인다
(§1.2). 따라서 *"적합이 나이를 먹으면 나빠진다"* 는 유효수명 가설 **그 자체가**
τ↓ ⟹ 개선의 **단조**를 예측한다. ⟹ **단조는 누수를 함의하지 않는다.**

게다가 **누수는 자료로 가릴 문제가 아니다** — §1.1–1.2 에서 코드 구조로 **불가능함이 연역**된다
(`predict_field` 는 `self._bank` 만 읽고, 채점 시점의 `self._bank` 의 최신 자료는 항상 예측 시각 −1 s 이하).

⟹ ★**처방(시급)**: `gates_b3b.py` 의 *"RV-3 의 누수 가설"* 가지를 **결과를 보기 전에** 철회하고,
용량-반응의 목적을 **`TUNED-AT-2S` 여부 하나로** 좁혀라. 그대로 두면 단조 결과가
**있지도 않은 누수**로 오귀속되고, 포화 결과가 **기제의 증거**로 과대 해석된다.
(⚠나는 `results_b3b.jsonl`·`b3c` 계열을 **열지 않았다** — 열람 범위 밖이다.)
