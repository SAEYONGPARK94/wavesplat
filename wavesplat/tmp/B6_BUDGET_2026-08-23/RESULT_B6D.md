# B-6d 결과 — ★**`CONTROL-FRAME-OK`** — **이번엔 배포 후보 구성 그대로** (12런)

**게이트 8/8 PASS** · 동결 분석기(`B-6c` 것을 그대로 상속) · `verdict_b6d.json`.
심사 토론의 **응용심사 요구**를 닫는 배치다.

## 0. 왜 필요했나
`B-6c` 가 `CONTROL-FRAME-OK 12/12` 를 냈지만 **그 실행은 재적합이 0회인 구성**이었다
(배포 전, 기본값 `None`). ⟹ **그 판정이 배포 후보 구성을 덮지 못한다** — 그것이 오늘 배포를
되돌린 사유 그 자체다. `B-9b` 가 `update()` 만 따로 재서 통과시켰으나
**`B-6c` 의 사전등록 형태(`update` + 제어 8점 렌더)로는 재통과시키지 않았었다.**

## ★1. 결과 — 재적합이 **실제로 발화·적용된 상태**에서 통과

| | `B-6c`(재적합 0회) | ★**`B-6d`(재적합 2회, 비동기, 실시간)** |
|---|---|---|
| 재적합 발화/적용 | 0 / 0 | ★**kick 2 · applied 2 (12/12 레코드)** |
| 제어 8점 렌더 | 0.98 ms | 0.99 ms |
| 추적 갱신 | 1.47 ms | **1.89 ms** |
| **프레임 비용** | 2.5 ms | ★**3.0 ms** |
| **프레임 예산(dt 67–100 ms)** | 12/12 | ★**12/12** |
| **100 Hz(10 ms) 예산** | 12/12 | ★**12/12** |
| 14 s 창 점유율(중앙/최악) | 0.273 / 0.390 | **0.280 / 0.392** |

★**재적합을 켰는데 프레임 비용이 2.5 → 3.0 ms 로 0.5 ms 만 늘었다**(비동기가 정지를 흡수).
★**음성 대조 유지**: 같은 타이머로 **채점 격자 전체**를 재면 `YS17` 이 **0.472 s > dt 0.100 s**
⟹ 이 배치의 타이머가 `B-6`/`B-6c` 와 같은 것을 재고 있다.

## ★★2. 배포 사슬이 **사전등록 형태로** 닫혔다
| 고리 | 배치 | 상태 |
|---|---|---|
| 재적합이 정확도를 번다 | `B-3`/`B-3b`/`B-3c` | ✅ 확증, 신선 창 복제 |
| 동기 재적합은 예산을 깬다 | `B-9`/`B-9b` 음성대조 36/36 | ✅ 774–867 ms vs dt |

| ★**사전등록 예산 형태 재통과** | ★**`B-6d`** | ✅ **12/12, 재적합 발화 확인** |
| 합성 회귀 위험 | 코드 불변량 시험 | ✅ **0** |

## ⛔3. 그래도 **기본값으로 만들지 않는다** (사유는 성능이 아니다)
★***비동기의 효과는 호출자의 벽시계 페이싱에 의존한다.*** `B-9` 가 그것을 실측했다 —
재생이 실시간보다 **494배** 빠르면 적합이 채점 뒤에 착지해 **설정은 켜져 있는데 실질은 꺼진**
상태가 된다. 기본값으로 만들면 그 함정이 **모든 재생 배치에 조용히 깔린다**
(= 이 저장소가 *"개입이 개입하지 않았다"* 로 여러 번 대가를 치른 부류).
⟹ ✅**명시 경로 + 상태 검사**가 옳은 배포 자세다:
```python
cfg.update(recommended_real_refit_config())          # {5.0, async True}
...
assert upd.bank_refit_health()['effective']          # 실질 작동 여부를 게이트로
```
그리고 그 함정이 조용하지 않도록 **경고를 코드에 심었다**(kick 은 있는데 applied 가 0이면 경고).
