# Discard audit — were the abandonment DECISIONS sound? (fable, 2026-07-23)

Scope per task: not "does the mesh regen reopen anything" (`tmp/REOPENED_BY_DATA_fable_2026-07-23.md`,
already answered — BF2 prose only) and not "are the surviving methods' designs sound"
(`tmp/METHODS_REREVIEW_fable_2026-07-23.md`, already answered). This document asks: **for every
method actually abandoned, was the abandonment itself sound, on any grounds?** Classified A–F per
task spec. MEASURED vs ARGUED tagged; file:line/command given wherever I re-derived a number myself
(marked "verified here"); everywhere else I read the primary result doc directly (not a memory
summary line) and cite it.

**Headline: no discard was flipped by this audit.** Every method with a genuinely negative or
FAIL verdict that I traced to its primary source turns out to rest on either (a) a multi-seed,
pre-registered, often self-corrected measurement (basis C — the large majority), (b) a structural
fact about the asset (basis A), or (c) literature pre-emption (basis B). **One item is a live,
already-flagged unresolved confound (A-7/A-7v2), already surfaced by `REOPENED_BY_DATA` — I did not
find anything new to add to it, just confirm it against the primary preregistration.** **One item
(better-net) has an acknowledged, never-repaired training-data confound, but it independently
failed twice more (a second held-out synthetic slice, and an HOS test) in the same direction, so the
confound is unlikely to be hiding a reversal.** The project's own discipline (pre-registration,
red-teaming, seed-replication) is visibly the reason bad discards get caught quickly here — several
times *within the same day* — rather than lingering; I looked for lingering ones and found very few.

   already documented by name (`E2_MESH_AUDIT_prereg_2026-07-13.md:94-101`), never resolved, cheap

   it would settle whether the project's own quasi-monochromatic/BF2 floor is an estimator

   story. This is not a new discovery of mine; it is `REOPENED_BY_DATA`'s own item 2, confirmed
   against its cited primary sources rather than re-summarized.

2. **Better-net matched-data retrain (#3).** Medium rank: the confound (10× training data) is
   acknowledged in the record and never repaired, but two independent, differently-designed tests
   (a disjoint held-out synthetic slice and an HOS test) already point the same direction, which
   caps the plausible size of a reversal. Worth doing only because the retrain is cheap relative to
   the size of the open question ("does comp-diverse training help at all"), not because there is
   live suspicion the current FAIL is wrong.

3. **Blind-current (Uc) estimation and track-level critic networks, primary-source read (#14, #15).**
   Lowest rank, flagged mainly for intellectual honesty: I classified these as sound from the

   ≥6 independent replications each, I judge them low-risk, but a 30-60 minute primary-source read
   would remove the one soft spot in this audit's own evidence chain.

## What this audit did *not* find

No case where a discard's *practical verdict* (ship it / don't ship it) was reversed. The closest
candidates — E-28 (#6), the diffusion-prior "representation wall" framing (#8), the ANM
"unrecoverable" claim (#9), and B-2's oracle-kp headline (#5) — are all cases where an *asserted
mechanism* was wrong and was **already caught by the project's own process**, most within the same
day or week, several with the correction publicly logged before being cited elsewhere. That is the
task's hypothesis playing out correctly, not failing to — the record shows the discipline catching
its own optimistic and pessimistic errors on a roughly even split (Run 1 vs Run 4 of the alt-methods
gate, #10, is the cleanest single example of both directions caught in one session). The one
genuinely open item is A-7 (#1), and it was already flagged, not newly discovered here.
