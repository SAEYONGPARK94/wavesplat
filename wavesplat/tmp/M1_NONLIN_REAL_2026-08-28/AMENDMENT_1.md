## 2. [MINOR-4] 검사기 `no-{}-arm` 열이 **영구히 `--`** — 오탐

**결함.** `tmp/_audit/check_batch_artifacts.py` 의 빈-dict-팔 탐지는
`gates*.py` 를 정규식 `['"][A-Za-z0-9_.+-]+['"]\s*:\s*\{\s*\}` 로 훑는다.
`gates_m1.py:683` 의 **자가진단 [2] 공허한-통과 시험**이

```python
empty = _run_all([], {}, {}, {'identical': {}, 'maxabs': {}}, runfree=False)
```

라 적혀 있어 `'identical': {}` 가 그 정규식에 걸렸다. **실제 빈 dict 팔은 0개**이므로 순수 오탐이다.

**왜 고치나.** 손해는 "틀린 경고 한 줄"이 아니다 — ★**경고가 항상 켜져 있으면 신호가 죽는다.**
21.6 h 배치가 끝난 뒤 이 열이 `--` 를 찍고 있으면 *"원래 그렇다"* 로 읽히고,
그때 **진짜 빈 dict 팔이 들어와도 아무도 못 본다**. 저장소가 이 부류로 이미 물렸다
(`gates_b7.py:46` 의 `'SHIP-TRACK': {}` 가 **당일 철회된 값**으로 돌았다).

**수리.** `dict(identical={}, maxabs={})` 로 표기만 바꿨다.
⛔**값은 비트 동일**이고 자가진단 [2] 가 그것을 확인한다(개정 전후 `공허한 통과 0건` 동일).

⚠**한 번 더 걸렸다**: 첫 수리에서 *설명 주석 안에* 그 패턴을 축자로 적었더니 열이 그대로 `--` 였다.
정규식은 **주석을 구별하지 않는다** ⟹ 주석도 패턴 없이 다시 썼다. `gates_m1.py` 의 정규식 히트 = **0**.
★교훈: *"이 열이 왜 켜졌는지"* 를 설명하려고 원인 문자열을 복사해 넣으면 원인이 그대로 남는다.

## 3. [MINOR-5] *"`gen_hos.py` 축자"* 가 문자 그대로는 거짓이었다

**결함.** `gen_m1.py` 의 `PairedHOS.evaluate_at` 은 `gen_hos.py:102` 를 *"축자"* 라 선언했는데
원본의 **가드 assert 2개를 뺀 채** 이식돼 있었다:

```python
assert X.ndim == 2 and X.shape == Y.shape
assert np.allclose(X, x[None, :]) and np.allclose(Y, y[:, None]), \
    'separable evaluate_at requires a regular meshgrid'
```

수치는 동일하다(정규 meshgrid 에서 두 구현은 같은 값을 낸다). 문제는 **선언과 사실의 불일치**다.
그리고 그 가드는 장식이 아니다 — 분리가능 재작성은 `X[i,j]=x[j]`·`Y[i,j]=y[i]` 규약에
**전적으로 의존**하고, 규약이 깨지면 이 함수는 **틀린 장을 조용히 반환**한다
(⛔예외도 경고도 없다). 21.6 h 를 그렇게 태우는 것이 정확히 저장소의 반복 결함 부류다.

**수리.** assert 2개를 복원했다. `evaluate_at` 본문은 이제 원본과 **AST 동일**하다(독스트링 제외).

**발화 확인** (런 0회 스모크 — `HOSSimulator` 인스턴스 없이 더미 `self` 로 호출):

| 입력 | 결과 |
|---|---|
| 배포 경로와 같은 `make_grid(...)` 정규격자 | ✅통과 (`Z.shape == (ny,nx)`) |
| 비정규 meshgrid (`X` 에 행별 오프셋) | ✅`AssertionError: separable evaluate_at requires a regular meshgrid` |
| 1-D 입력 | ✅`AssertionError` |

★**실제 경로가 안전한 근거**: `wavesim/pipeline.py:192,200` 의 두 호출 지점이 모두
`make_grid` = `np.meshgrid(x, y)` 산물을 넘긴다(`gt_generator.py:25`) ⟹ 가드는 통과한다.

## 4. [MINOR-6] 나이퀴스트 서술이 **자유파만** 덮고 있었다 → 공시 추가

**결함.** PREREG §1.1 은 `jonswap_components` 가 낳는 **자유파** 성분이 격자에 담기는가만
따졌다(`k_max = 2.97360 ≤ nyq = 3.01593`). 그런데 HOS `M=3` 이 만드는 것은 **속박 조화**(2·3차)이고
그 파수는 `2k`·`3k` 다. `wavesim/hos_simulator.py::_to_spectral` 은 `|m| < N/2` 밖을
**절단**한다(⛔앨리어싱이 **아니다** — 되감기지 않고 사라진다).

**실측** (동결 24 에피소드, 성분 540개):

| | 문턱 | 해당 성분 |
|---|---|---|
| 3차가 잘리는 자유파 | `k > nyq/3 = 1.00531` (`λ < 6.250 m`) | **270 / 540 = 50.0%** |
| 2차까지 잘리는 자유파 | `k > nyq/2 = 1.50796` (`λ < 4.167 m`) | **186 / 540 = 34.4%** |

✅**피크는 안전하다**: `k_p = 0.33040` ⟹ `3·k_p = 0.99120` = 나이퀴스트의 **32.9%**.

**수리.** PREREG 에 **§1.1a** 를 신설해 공시하고, §3「주장하지 않는 것」에 **8번**을 추가했다.
정확한 서술 = ***"이 코퍼스의 비선형성은 스펙트럼 피크 부근에서 충실하고 `λ ≲ 6 m` 꼬리에서는
속박 조화가 절단돼 과소표현된다"*** ⟹ 이 배치의 HOS 팔은 **절단된 M=3** 이다.

**판정 무영향.** 문턱·팔·표본·라벨·해석 규칙 어느 것도 이 사실에 의존하지 않는다.
⚠**방향은 보수적**이다 — 비선형성이 과소표현되면 결과는 `HOS ≈ LIN` 쪽으로 끌리므로
`BREAKS` 가 나오면 **과소평가된 효과**다. ⛔반대로 `HOLDS` 는 *"완전한 M=3 에서도 유지"* 로
**일반화되지 않는다**(그래서 §3-8 에 걸었다).
(3차까지 담으려면 `nyq ≥ 3·k_max = 8.92` ⟹ `1728×1152` = 셀 **9배**. 예산 밖 ⟹ 재는 대신 공시.)
