## 1. 설계 confound (σ₀ 미변경) — **OK**
`_build_bank`(공유, T/L/N 전 팔 동일 경로) 코드 확인: `sig0=float(nfrac*Hs)`(kp와 무관, meta에서 직접)는
posterior의 **noise-floor 스케일**(`s2=(exp(log_smult)*sigma0)^2`)에만 관여하고, `kp_e`는 **완전히 다른
역할**(`kxb=kxn*kp_e, kyb=kyn*kp_e` — 후보 wavenumber bank의 **격자 배치**)을 한다. 두 양은 손실 함수 안에서
기능적으로 독립(곱셈적으로 얽히지 않음) — **kp만 바꾸는 것이 진짜 단일-변수 개입**이며 σ₀ 고정은 confound가
아니라 올바른 통제. M-3도 동일하게 σ₀ 불변이었으므로 M-3↔M-3G 비교도 일관. **coordinator 판단(confound
아님)에 동의.**

## 2. 판정규칙(goalpost) — **대체로 OK, FIX 2건**
- **PASS 바(+0.08)가 E-B2K 원 PASS 바(+0.02)보다 훨씬 높다는 게 goalpost 이동 아니냐**는 우려에 대한 답:
  **아니다, 의도적 재정의이고 올바르다.** 원 바(+0.02, wild<.05)는 "효과가 **존재**하는가"를 묻는 바였다 —
  실은 M-3의 sensor-kp 결과(+0.0222, wild .043)는 이 **원래 기준으로는 이미 PASS**였을 것이다(그런데도
  M3_RESULT.md는 정확히 "FLAG"로 불렀음, 옳은 판단). M-3G가 묻는 질문은 "존재하는가"가 아니라 **"원래
  크기(~+0.14)로 회복하는가"**이므로 더 높은 바(+0.08≈57%)가 필요 — **재정의가 질문에 맞게 이뤄졌다.** 단
  **prereg 본문에 이 구분을 명시할 것을 권고**(현재는 암묵적) — 안 그러면 "왜 +0.02가 아니라 +0.08이냐"는
  사후 의문에 답이 문서에 없다.
- **[FIX] T−N에 대한 동결 바가 없다.** 판정표는 T−L만 정의(PASS/FAIL/PARTIAL 3단), T−N은 "M-3와 동일 방식
  보고"라고만 돼 있어 **T−N 결과의 사후 해석에 자유도가 남는다**(M-3서 이미 거의 소멸 — +0.0074, n.s. — 이걸
  M-3G가 살짝만 움직여도 "부분 회복"이라 부를지 "여전히 죽음"이라 부를지 사전 미정). 권고: T−N에도 동일
  형식의(더 낮은 시작점 반영해 다소 완화된) 바를 동결하거나, **명시적으로 "T−N은 기술적 보고만, 헤드라인
  판정 대상 아님"**이라고 못박을 것 — 지금 상태로 두면 결과 나온 뒤 서술의 여지가 생긴다.
- **PASS(3중 연언) vs FAIL(단일 조건) 비대칭**은 의도적이고 적절 — "회복" 주장이 더 무거운 증거를 요구받는
  건 upward-claim에 대한 정당한 보수성(방향 라벨 발급 규율과 정합). **OK.**
- ≥8/11 기준은 이항(50/50) 기준 단독으론 약함(P(X≥8|coin)≈0.113)이나 wild p<.05와 AND로 묶여 있어 "1~2개
  극단 바다가 결과를 지배"를 막는 **보조 로버스트니스 체크**로 기능 — 이 역할로는 **OK**.

## 3. Beamform kp 캐시 — **결정론성은 OK, but FIX(중요): train/eval 기하 불일치**
- **결정론 확인(OK)**: `beamform_top`(`d18_relax_estimator.py:53`)은 순수 argmax grid-search, rng 없음 —
  8000 scene 1회 캐시 후 9회 재사용은 완전히 안전(재현성 문제 없음).
- **★기하 불일치(FIX, 이 red-team의 최대 발견)**: prereg는 "beamform·train·eval 동일 recipe(2단 n=120)"라
  train/eval 일관이라 주장하나, **"레시피(함수 호출)가 같다"와 "입력 점군의 통계가 같다"는 다른 문제다.**
  - eval 아레나(`e60k_hos_arena.py`): return-power 지수분포 로터리 + **12-bin range-stratified** 선택,
    N_OBS≈600(env override), 실제 LiDAR 관측각/거리 분포 모사.
  - 훈련 scene(`d3_prior_net_data.py::sample_obs`): **N_OBS=400 고정**, `'fixed'` 모드(전체의 **1/3**)는
    `r_fp = 0.09·λ`(**footprint 지름 = 0.18λ**)의 원판 안 균일 지터 — **La Jument 실측 0.11λ("물리 이점
    소멸") 사례와 동급이거나 더 나쁜 개구**. `'moving'` 모드(2/3)는 대각선 왕복 트랙(변위 최대 2λ)이라 진짜
    synthetic aperture를 얻지만, `'fixed'` 1/3은 사실상 **점-센서**에 가깝다.
  - M-3 자신의 헤드라인 원인이 정확히 "작은 개구가 장파 kp를 못 resolve"(Tp13, beamform kp +37% 편향)였다
    — 그런데 훈련 데이터의 1/3이 **구조적으로 이보다 나쁜 개구**를 갖는다. 즉 캐시될 `kp_beam`은 (a) 2/3
    scene에서는 괜찮은 synthetic-aperture 추정치, (b) 1/3 scene(`ucp==0`)에서는 심하게 편향/불안정한
    추정치 — **인위적으로 이질적인 라벨 노이즈**를 훈련에 주입할 위험. 이는 "센서-실현"을 대표하는 것일 수도
    있지만(실제 배치도 fixed-staring geometry를 쓸 수 있음), **의도치 않은 heterogeneity**일 수도 있어
    사전 확인 없이는 결과 해석이 위험하다.
  - **권고(발사 전, 값싸고 빠름 — meta에 이미 `ucp` 필드 존재, 추가 계측 불필요)**:
    1. `kp_beam.npy` 계산 직후, 8000 scene 전체에 대해 `kp_beam/kp_e`(oracle) 비율의 분포(median/IQR/tail)
       보고.
    2. **`ucp==0`('fixed', 1/3) vs `ucp>0`('moving', 2/3)로 분리**해 같은 비율 분포 — `fixed` 서브셋의
       편향/분산이 확연히 나쁘면(예상됨) 그 사실을 결과 해석에 명시.
    3. 1e-3 floor(`beamform_kp`의 `max(hypot(bx,by),1e-3)`) 히트율 보고 — 0에 가까워야 정상.
    4. **자기검사(self-check) 1개 추가 권고**: `kp_beam := kp_e`(oracle 그대로)로 코드 경로를 통과시켜 **원본
       E-B2K 체크포인트/손실과 bit-identical**한지 확인 — kp 교체 배선 자체가 다른 부작용 없음을 증명(e60k의
       "refactor bit-identity" 게이트, m3의 SELF-CHECK와 같은 정신, 코드 변경 자체의 정합성 검증).
  - **FATAL 격상 안 하는 이유**: 이질적 kp 품질이 섞인 채로 훈련하는 것 자체가 "진짜 센서 배치의 다양한
    기하"를 반영한다는 해석도 가능(전부 나쁜 게 아니라 일부만 나쁨 = 오히려 더 현실적). 문제는 **진단 없이
    결과를 해석하면 오도될 위험**이지 실험이 무효라는 뜻은 아님 — 그래서 FIX(사전 진단 의무화)로 충분.

## 4. 최난셀 지배 + VOID 규칙 — **FIX(보고 방식), VOID 유지는 OK**
- **최난셀 지배 위험은 실재**: M-3서 Tp13_Hs5 하나가 T−L의 가장 극적인 반전(oracle +0.613→sensor +0.056)을
  보였다 — §3의 개구-편향 기제(장파+작은 개구)가 바로 이 셀에서 가장 강하므로, 훈련 kp도 이 Tp 근방
  scene에서 유사하게 나쁠 개연이 높다(Tp13은 훈련범위 Tp∈[5,11] **밖**이라는 점도 주목 — 훈련 kp 편향의
  분포가 Tp13 자체에서 어떻게 외삽되는지는 **직접 모름**, 이것도 불확실성 요인으로 병기할 것).
  - **권고**: E60K_RESULT의 R5(leave-one-sea-out) 관행을 그대로 재사용 — M-3G 최종 보고에 **(a) 전체 11바다
    풀 결과 (b) Tp13_Hs5 제외 10바다 결과**를 나란히 제시. 하나가 다른 하나와 크게 다르면(예: 전체는
    PARTIAL인데 Tp13 제외시 PASS 문턱을 넘는다든지) **그 자체가 핵심 발견**이지 숨길 정보가 아님 — 나란히
    보여주는 것이 오도를 막는 유일한 방법.
- **VOID(smult std>0.5) 유지는 OK**(E-B2K와 동일 기준 재사용, goalpost 이동 아님) — **단 이 규칙은 "시드간
  불안정"만 잡지 "시드 전체가 일관되게 더 나쁜 값으로 수렴"(예: §3의 이질적 kp 라벨 노이즈로 인한 체계적
  편향)은 못 잡는다.** VOID 미발동 = "학습이 안정적으로 수렴했다"는 뜻이지 "kp 라벨이 좋았다"는 뜻이 아님 —
  §3 진단과 VOID는 **서로 다른 것을 검사**하므로 하나가 다른 하나를 대체 못 한다(둘 다 필요).

## 5. 사전확률 55/45 — **서사편향으로 보이지 않음, 오히려 반대 방향 여지 있음(관찰)**
55/45가 "좋은 소식(B-2 생존)"쪽으로 살짝 기운 것 자체는 자연스러운 근거(smult 지문 T~3.2 vs L/N~1.8이
kp와 무관한 축이라는 F-4식 논리)가 있어 **명백한 편향은 아니다.** 대칭감사 차원에서 반대 방향 논거도
확인: **M-3 자신의 데이터가 오히려 (b)회복에 더 힘을 싣는다** — Tp13_Hs5에서 L·N이 **oracle-훈련·
sensor-평가**(train/eval 불일치)만으로 0.057→(추론시 kp만 바꿔도)0.508까지 극적으로 좋아졌다는 사실은,
L·N의 원래 실패가 상당 부분 "학습된 격자 배치와 추론시 격자 배치의 어긋남" 문제였음을 시사한다 — **이건
바로 재훈련(=격자 배치를 다시 일치시킴)이 직접 겨냥하는 메커니즘**이다. 즉 M-3의 증거를 기제적으로 읽으면
55%보다 **회복 쪽 확률이 더 높다고 주장할 여지도 있다.** ⟹ 55/45가 편향이라면, 오히려 **M-3 prereg에서 한 번
틀린 것에 대한 과잉 비관 보정**(THESIS_FRAMING §11의 "감쇠 진동" 패턴)일 가능성 쪽이 더 크다 — 두 방향 다
과녁 밖은 아니라서 **판단을 강제하지 않음, 관찰로만 기록.**
