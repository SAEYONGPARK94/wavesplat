# 1. ★★★BLOCKER B-1 — `sigma0` 계수는 손잡이가 아니다 (개입 지점 부재 3회째)

## 1.1 BRIEF 의 주장

> §1 Q-A: "`sequential_update.py:840` 의 **`sigma0 = 0.05 * Hs_obs` 가 하드코딩**돼 있다.
> 이것이 bank 경로의 **사전 잡음 규모** = λ 의 구조적 대응물이다. **설정 불가**."

**두 군데가 틀렸다.**

## 1.2 사실 ① — `sigma0` 는 실효적으로 하드코딩이 아니다 (`MEASURED`)

`wavesplat/optimizer/bank_mmse.py:188-194`:

```python
for smult in (1.0, 3.0, 10.0):
    s2 = (smult * sigma0) ** 2
    ...
    vr = float(np.sqrt(np.mean((fv - zv) ** 2)))
    if best is None or vr < best[0]:
        best = (vr, pexp, smult, gam)
```

적합이 **held-out 예측 오차(`vr`)로 잡음 배수 `smult ∈ {1,3,10}` 를 이미 스스로 고른다.**
실효 잡음은 `smult · sigma0` 이고, 이 격자는 **10배 범위**를 덮는다.
BRIEF 가 제안한 계수 격자 `c ∈ {0.02, 0.05, 0.10, 0.20}` 도 **10배 범위**다.
⟹ 두 격자는 **에일리어싱**된다.

## 1.3 사실 ② — 스윕 양 극단이 **동일 적합**을 낸다 (`MEASURED`, 내가 실행)

# 2. ★★★BLOCKER B-2 — `GAUSS-*` 팔은 존재하지 않는 팔이다

## 2.1 BRIEF 의 주장

> §3 표: `GAUSS-L1e4` = `real_domain_gate=False`, λ=1e-4 → "Q-B — 오늘의 새 기본값"
> §1 Q-B: "역사적 근거: bank 가 v2_konly 를 약 **2배** 이겼다 (… 0.858/0.927/1.048 vs
> 0.498/0.666/0.718)"

## 2.2 사실 — 게이트를 끄면 **v2_konly 가 아니라 learned 로 간다** (`MEASURED`, 내가 실행)

`sequential_update.py:487-489` — 게이트가 안 걸리면 `_auto_select_init()` 가 호출되고,
그 라우터는 `n_selected >= 8` 이면 **`learned`** 를 고른다(`:708`).

창 `AA15a w5`, 출하 `DEFAULT_CONFIG` 그대로:

```
real_domain_gate=True  -> route='bank_mmse'  real_gate=True   n_selected=None   init  4.1s
real_domain_gate=False -> route='learned'    real_gate=False  n_selected=30     init 86.2s
```

- 라우트는 **`learned`**. `n_selected = 30` = **`max_n` 상한 포화**
  (`memory/project_routability_2026-08-01.md`: "실측 22/30이 `n_sel` 상한 30에 포화").
- 비용 **21배**(4.1 s → 86.2 s). 30창 × 2λ = 60런 ≈ **86분 + GPU**.

⟹ BRIEF 가 인용한 "**2배**" 근거는 **v2_konly** 의 숫자다. 팔과 대조군이 **다른 물건**이다.

## 2.3 더 나쁜 것 — 그 실험은 **이미 실행됐다** (`MEASURED`, 원자료 인용)

`docs/HANDOFF_OPUS_2026-07-26.md:33-36`:

> "(ii) Blind auto (W5 official): **routes learned 30/30**, guard 0/30 (real bf_peak_ratio
> 0.108–1.00 …), **median 0.836 vs hand 0.809, worse on 21/30 windows and 5/5 records**
> → bars B1 FAIL … **the unified claim is scoped to synthetic.**"

그리고 `memory/project_wp_real_2026-07-26.md`:
정상 27창 hand **0.744** vs learned **0.805**, learned **6/27승**, 양측 **p=0.0046** = **유의한 패배**.

⟹ **Q-B 는 답이 알려진 질문의 재실행이다.** 사전확률로 "bank 승" ≈ **0.9 이상**.
λ 를 1e-3→1e-4 로 바꾼다고 21/30·5/5 패배가 뒤집힌다는 근거는 **0건**이다.

## 2.4 게이트가 왜 생겼는가, 그 이유는 여전히 유효한가 (감사 각도 4의 직접 답)

**생긴 이유** (`sequential_update.py:430-445` 주석 + 원자료 추적):
- `tmp/confirm2_2026-07-27/RESULT_CONFIRM2.md:54-55` — "실측 입력에서 auto 는 여전히 비활성이어야
  함 … **실측 기본값 사고 리스크(R1)는 코드 게이트 없이는 존속**".
- `docs/HANDOFF_OPUS_2026-07-26.md:33` — 위의 30/30 라우팅 + 21/30 패배.
- `memory/project_persona_debate_2026-07-26.md:34` — ★**서면 지시**:
  "**run.py 기본값(auto)을 실측 레코드에 쓰지 말 것.**"

**여전히 유효한가 — 예, 그리고 오늘 더 강해졌다**:
- 라우터 입력 `n_selected` 는 실측에서 **상한 30 포화**(내 측정) + **시드 불안정**

⟹ **게이트를 열어 얻은 승리는 배포 주장으로 쓸 수 없다.** 그 구성은 (a) 승인 범위 밖이고
(b) 명시적 금지 지시 대상이며 (c) 라우터 신호가 퇴화한 상태다.
게다가 이기더라도 "게이트 off + learned + λ" **3요인 묶음**이라 단일 원인 이름을 못 붙인다
(⛔S3/S4/S6 의 "묶음에 단일 원인 이름" 금지 — **4회째 재발**).
