## §2. 짝 단위 · 창 배치 · 창 간 상관 (★결과 전에 동결)

### 2.1 두 층의 단위
- **창(window)** = `(record, i0)`. 창 하나가 **한 번의 Phase-1 적합 + t0 에서의 필드 예측**이다.
- **레코드(record)** = 그 레코드의 창별 상대차의 **중앙값 1개**.

### 2.2 ★**주 검정의 짝 단위는 레코드다** (창이 아니다)
같은 레코드의 창들은 **같은 해상**에서 나온다 ⟹ 독립 추출이 아니다.
저장소는 이미 이 실수의 대가를 치렀다: 08-12 헤드라인 `85/100 p=4.8e-13` 이
**클러스터 바닥 p=0.031** 로 무너졌다(레거시 생성기, 시드 0–4). **같은 구조가 여기 있다.**
⟹ **헤드라인 p 는 레코드 수준 p 다. 창 수준 p 는 부차이고, 절대로 헤드라인이 될 수 없다.**

### 2.3 창 배치 규칙 (런 전 결정, JSON 으로 동결)
레코드별로 `W_rec`(기억창)·`lead_max`·간격을 **하나의 식**으로 정한다(단일출처, `corpus_r1.py`):

```
lam_ref, Tp_ref  : 런 전 특성화(레코드당 1회) — 창별로 다시 재지 않는다.  ★§2.3.1 의 함정 참조
L_short          = 유효 박스의 단축 [m]  (dead-pixel kill 후)
W_rec            = clip(4.0 * Tp_ref, 10.0, 60.0)          [s]   기억창
lead_max_rec     = clip(3.0 * Tp_ref, 10.0, 25.0)          [s]   조우예보 지평 (SECONDARY 전용)
gap_rec          = max(W_rec + lead_max_rec, 10.0 * Tp_ref) [s]   창 중심 최소 간격
r_max_rec        = min(1.70, 0.42 * L_short / lam_ref) * lam_ref  [m]  팬 외경
r_min_rec        = r_max_rec / 5.0                                [m]  팬 내경
h_sensor_rec     = 0.19 * lam_ref                                 [m]  ⚠**스케일 모형** 마스트
d_ref_rec        = 1.40 * r_max_rec                               [m]  confidence 기준거리
U_rec            = 0.16 * c_p(lam_ref, depth)                     [m/s] 선속
```

**왜 전부 λ 로 스케일하는가**: 후보를 넓히면 마이크로 레코드(BS, 패치 13–19 m)가 들어오는데,
절대 단위를 고정하면 **팬/λ 비가 레코드와 교락**된다. λ 스케일은 그 교락을 제거한다.
⚠**그래도 `r_max/λ` 는 레코드마다 다르다**(패치가 제한하므로). ⟹ **`r_max/λ` 를 층화 공변량으로
런 전에 기록하고 보고한다.** ⛔소리 없이 뭉뚱그리지 마라.

**상수의 근거 (MEASURED, 이 세션에서 계산)**:
- `0.42` 는 d3 보다 **보수적**이다 — d3 는 AA 에서 `r_max = 40 m ≈ 0.63·L_short`, YS17 에서
  `100 m ≈ 0.47·L_short` 를 썼다. 이 식은 YS17 에서 **≈18–90 m**(d3: 20–100), AA15a 에서
  **≈5.3–26.5 m**(d3: 8–40) 를 준다. **항로도 박스 안에 들어가야 하므로 보수 쪽을 택한다.**
- `0.16` 은 d3 의 스케일 레코드 실측비의 중앙값이다(AA15a **0.136** · AA14 **0.176** · AA15b **0.160**).
  ⚠**d3 의 YS17 은 0.221 이므로 이 식은 그것을 재현하지 않는다**(YS17 에서 U ≈ 1.45 m/s).
  1.45 m/s 는 `reference_agreed_operating_point` 의 **판정용 실측 창 1.2–2.4 m/s 안**이다.
  ⛔**설계 선속 11.3 m/s 와 혼동 금지.**
- `h_sensor = 0.19·λ` 는 YS17 에서 ≈10 m(현실적 마스트)를 주지만, LJ 계열에서는 ≈57 m 가 된다.
  ⟹ ⚠**물리적 마스트가 아니라 스침각을 λ-정규화로 고정하기 위한 스케일 모형**이다. 그렇게 적을 것.

### 2.3.1 ★λ 를 어디서 가져오는가 — **패치 인공물 함정**
⛔**LJ 계열에서 창별 `characterize()` 의 `lam_p` 를 쓰지 마라.** 저장된
`results/direction3/falcon_real_operator_LJ18g.json` 의 창별 중앙값은 **160.8 m** 인데,

*"characterize() lam_p/c_p are patch artifacts — analysis uses `*_ref`"* 라 적었다.
⟹ **패치가 λ 보다 작으면 FFT 가 λ 를 과소추정한다.** `lam_ref` 를 쓴다.
⟹ 그 결과 **LJ18g 의 진짜 개구비는 162/300 = 0.54 λ** 이지 162/160.8 = 1.01 λ 가 아니다.

**창 개수**: `m = 7` (레코드당). 균형설계 — 병목은 YS17(450 s)이고 위 식으로 정확히 7개가 나온다.
창 시작점은 `np.linspace(lo, hi, 7)` 의 정수화이고 **런 전에 JSON 으로 동결·md5** 한다.

### 2.4 인접 창 상관을 어떻게 다루는가
1. **설계로 줄인다**: 중심 간격 ≥ `max(W+lead, 10·Tp)` ⟹ 기억창이 겹치지 않고, 중심이 10 Tp 이상 떨어진다.
   (ARGUED: 해상 결맞음 시간은 보통 수 Tp 이므로 10 Tp 는 보수적. **MEASURED 아님.**)
2. **검정으로 무력화한다**: 주 검정 단위가 레코드다(§2.2) ⟹ 창 간 잔존 상관은 **레코드 중앙값 안으로 흡수**되고
   주 p 를 부풀리지 못한다.
3. ★**측정한다**: `D-1` = 창 수준 상대차의 **레코드 내 급내상관 ICC**(기술통계, 가설 아님).
   ⟹ **다음 배치가 표본을 제대로 사이징할 수 있게 하는 유일한 산출물이다.**

### 2.5 ⛔중첩 축을 n 에 합치지 마라
- ⛔**기억창 W ∈ {10,20,40} 를 n 에 합치지 마라** — 같은 창의 **중첩된 관측 부분집합**이다. **W 는 `W_rec` 하나로 동결**, 나머지는 SECONDARY 민감도.

   그때의 산출은 검정이 아니라 **MDE 진술 + 창 수준 기술통계 + `D-1` ICC** 다.
   (MDE, 검정력 0.80 기준 최소 레코드 승률: n=5 → **0.956**, 6 → 0.964, 7 → 0.969,
   8 → 0.896, 11 → 0.857, 13 → **0.818**. ⟹ **n≤7 은 "거의 결정론적 효과"만 잡는다.**)
5. **동등성 검정은 대안이 아니다** — n_rec=5 의 분포무관 95% 중앙값 CI 는 사실상 (min, max) 라
   TOST 가 어떤 유의미한 경계도 못 준다. ⟹ **n 을 늘리는 것 외의 대안은 없다.** 정직하게 적는다.
6. **창 수준 문턱**(IUT 와 부차 전용, 단측 α=0.05 정확 이항, m=7 ⟹ n = 7·n_rec):
   **n=56 → 35/56**(p=0.0407) · **n=63 → 39/63**(p=0.0385) · **n=70 → 43/70**(p=0.0361) ·
   **n=77 → 47/77**(p=0.0338).

### 4.1 ★`kp_obs` 는 오라클이 아니다 (설계의 핵심 한 줄)
- **`R-SHIP-KP`·`R-VP-KP`·`R-VPONLY-KP` 의 kp 는 `bank_mmse._beamform_top` 2단 줌을
  `팬 관측 P,z 에만` 적용해 얻는다** (`optimizer/bank_mmse.py:150-155`, `kp_hint=None` 경로).
  ⟹ **GT-free · 인과적 · 센서 실현가능.**
- ★**180° 모호성 해소가 따로 필요 없다** — `_beamform_top` 은 부호 있는 `(kx,ky)` 를
  `kx·x + ky·y − ω t` 위에서 쓸어 **분산관계로 방향이 이미 결정**된다.
  ⛔`d3_falcon_real_operator.resolve_direction()` 은 **전체 프레임**을 쓰므로 **패치 오라클**이다.

- ⟹ **#10 − #5 의 차이가 "센서만으로는 못 사는 kp 품질"의 값**이다. 이것이 저장소가
  `d3_falcon_real_operator.py:13-15` 에서 *"external kp beats blind spectral placement"* 라 적고도
  **한 번도 분리해 재지 않은 양**이다.

### 4.2 ⚠**confidence 가 팬 대역에서 포화한다** (MEASURED, 산술)
`observation_weights = clamp(cosθ /(d/d_ref), 0, 1)` (`model/confidence.py:38-41`).
`d_ref = 1.25·r_max`, 팬 `d ∈ [r_max/5, r_max]`, 마스트 `h = 0.19λ` ⟹ **근거리는 전부 1 로 클램프**되고
원거리에서만 변한다. ⟹ ★**W5 의 `vp_weighting` 축은 실측 팬 위에서 사실상 무력**이다.
⟹ **가중 팔을 이 배치에 넣지 않는다**(런 낭비). 대신 **G-6 이 `mean(conf)`·`min(conf)` 를 팔 간
비트 동일로 검사**한다.

## §5. IUT 게이트 — ★**우리에게 불리하고, 실제로 실패할 수 있다**

> **IUT (교집합-합집합 검정: 아래 셋을 **전부** 기각해야 통과)**
> **IUT-a** `R-SHIP-KP < R-ZERO` — **PRIMARY 의 대조 팔에 기술이 있는가**
> **IUT-b** `R-VP-KP < R-ZERO` — **PRIMARY 의 처치 팔에 기술이 있는가**
> **IUT-c** 위 둘의 **레코드 방향 일치** ≥ `ceil(0.75 · n_rec)` 레코드

- **IUT-a/b 는 창 수준**에서 단측 α=0.05 정확 부호검정(문턱 = §3.3-6: 56→35 / 63→39 / 70→43 / 77→47).
  **IUT-c 의 요건**: `ceil(0.75·n_rec)` = n_rec 8→**6/8** · 9→**7/9** · 10→**8/10** · 11→**9/11**.
  **IUT-c 는 방향 요건**(p 값이 아니다 — 2^n 벽을 피하기 위해 의도적으로 검정이 아니게 두었다).
- **왜 IUT 만 창 수준인가**: IUT 는 *큰 효과의 전제 점검*이다(기술 있음 vs 없음; 기대 승률 ≈ 1).
  단일 레코드가 끌고 가는 실패 모드는 **IUT-c 가 따로 막는다.** 반면 PRIMARY 는 *작은 효과* 비교라
  클러스터 팽창이 실제 위험이므로 레코드 수준이어야 한다. **이 비대칭은 의도적이고 결과 전에 적는다.**
- ★**실패하면 곧바로 `FAIL (NO-SKILL-ON-REAL)`** 이고 **PRIMARY 는 해석하지 않는다**(기록만).
- ★**이 게이트는 실제로 실패할 수 있다**: 오늘의 `R-SHIP-BLIND` 가 정확히 여기서 죽었다
  (0.265 > 0.250). 그게 이 설계의 요점이다. **`R-ZERO` 는 항등적으로 0.25 이므로 게이트가
  위음성일 수 없다**(G-5 가 그것을 검사한다).

### 5.1 ★사전 선언된 예상 (결과 전에)
- **`R-SHIP-BLIND` 는 IUT 를 통과하지 못할 것으로 예상한다.** 통과하면 **오늘의 붕괴는 OOD 사실이
  아니라 하네스 버그**였다는 뜻이고, 그 경우 **이 배치의 §0 서술 전체를 철회**한다.
  ⟹ 이 팔은 "오늘의 미사전등록 관찰"을 **사전등록된 관찰로 승격**시키는 것이 유일한 목적이다.

## §6. PRIMARY — **1개**

> **P-1 (단측)** **`R-VP-KP < R-SHIP-KP`**

### 6.1 왜 `R-VPONLY-KP` 가 PRIMARY 가 아닌가 (결과 전에)
W5 의 −25.3% 를 낸 `L-VP-ONLY` 는 **4요인 묶음**이었다(결합적합 · `clamp_steepness` 투영 ·

## §11. 정지 규칙

- **IUT 실패** → **`FAIL (NO-SKILL-ON-REAL)`** 로 기록하고 **실측 전이 축을 이 프로토콜에서 종결**한다.
  단 **W5 의 합성 결론(−25.3%)은 그대로 유효**하다 — 실측 실패는 합성 측정을 무효화하지 않는다.
  그리고 그 경우 **다음 질문은 "VARPRO" 가 아니라 "왜 gradient 경로가 실측에서 기술이 없는가"** 다
  (후보: OOD 체크포인트 · 팬 지지집합 · 비선형성 — HOSGATE 가 희소 표현에 3.6배 하중을 실측했다).
- **IUT 통과 + P-1 널** → **`REAL-NULL`**: **VARPRO 는 실측으로 전이되지 않는다.** 축 종결.
- **P-1 통과 + `S-1` 실패** → **`REAL-TRANSFER / BEHIND-MMSE`**: 정직한 문장은
  **"gradient 경로는 개선됐지만 저장소가 실제로 배포하는 실측 추정기(bank-MMSE)에는 여전히 진다."**
  ⟹ 배포 권고 **불가**.
- **P-1 통과 + `S-1` 통과** → ★**`REAL-TRANSFER`**: 배포 후보로 승격하되 **§9-9 조건 전부** 만족 시에만.
- **`n_rec < 8`** → **`PILOT`**: 검정 없음. MDE·ICC·기술통계만 보고하고,
  **다음 배치의 사이징 근거**로만 쓴다. ⛔`PASS`/`FAIL` 어휘 금지.
