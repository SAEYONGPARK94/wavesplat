## 4. 창 안/밖 분해 (H3) — 두 종류의 손상이 **둘 다** 있다

혼잡 수준(중앙): `window` → `all_frame`

| 셀 | window | all_frame | 밖−안 |
|---|---|---|---|
| `ORA-WPHI-0STEP`(진실) | 0.00576 | 0.00577 | +0.00001 |
| `ORA-WPHI-NT` | 0.02222 | 0.15536 | **+0.13314** |
| `ORA-WPHI-NOREG` | **0.00589** | 0.02308 | +0.01719 |
| `AUTO-NT` | 0.03773 | 0.19528 | +0.15754 |

⟹ 진실은 창 안팎이 **같다**(+0.00001) = 일반화가 완벽하다.
⟹ 정규화를 끄면 창 안은 진실 수준으로 돌아오지만 **밖은 여전히 +0.01719 남는다**
(진실의 ~1700배지만 `NT` 의 13%). ⟹ ★**"창 안 손상"은 정규화항이 만들고,
"창 밖 손상"은 대부분 같이 사라지지만 전부는 아니다.** 남는 몫이 E-D 의 지지집합 밖 문제일 것이다
— ⛔이건 **추정이지 측정이 아니다.**

## 5. ⛔인용 제한
- ⛔**"옵티마이저가 자기 목적함수를 못 내린다"** — `window_resid` 는 **무가중**이고
  학습 목적함수(신뢰도 가중 + λ 항)와 다르다. 허용: **"학습창의 무가중 데이터 적합에서도
  진실보다 나쁘고, λ 를 0 으로 두면 회복된다."**
- ⛔★**"정규화를 끄면 배포 성능이 좋아진다"** — 혼잡 PRIMARY **10/16, p=0.45 로 문턱 미달**.
  허용: **"오라클 초기화에서는 −84%(16/16), 배포 팔 혼잡에서는 중앙 −11.8% 이나 10/16 으로 미달,
  배포 팔 희소에서는 −64.6%(14/16)."**
- ⛔`0STEP` nRMSE=0 을 **표현 충분**으로(동어반복) · ⛔`ORA-*` 를 배포 성능으로(묶음·출하 불가).
- ⛔H6 순차 제거를 **직교 분해**로 · ⛔혼잡 판정을 희소로 일반화 · ⛔S1–S4 와 풀링.
- ⛔**처방 주장** — `λ` 를 바꾸는 것이 배포에 좋다는 근거는 **아직 없다**(§2).
- ⛔지연·벽시계 · ⛔실측 일반화.
