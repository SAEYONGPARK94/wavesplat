# S8 AMENDMENT 2 — 실행 전 게이트가 **내 낡은 상수** 때문에 FAIL 했다 (결과 0건 상태)

2026-08-10 21:55 개정. **S8 결과 파일은 존재하지 않는다**(`results.jsonl` 없음, 배치 미실행).
`gate.py` 만 수정하고 재동결한다. `PREREG.md`·`AMENDMENT_1.md`·`analyze_s8.py`·MDE 산출물은
**손대지 않는다**(md5 불변).

## 1. 무슨 일이 있었나
18:24:40 에 게이트가 **FAIL** 을 찍고 `chain.sh` 가 사전등록 규칙대로 배치를 **돌리지 않았다**.
⟹ **fail-closed 설계는 의도대로 작동했다.** 그러나 FAIL 의 원인은 데이터가 아니라 **검사 코드**였다:

```
### G-4 충돌 0 (기존 집합과 파일명 교집합)
  기존 19 집합과 교집합: 0  ✅
  시드 전부 24-31       : ⛔        ← ★이 줄
```

`gate.py` 를 S7 것에서 유도할 때 `sed` 가 `SEEDS = range(24, 32)` 는 바꿨지만
`g4_collisions()` 안의 **하드코딩 `24 <= s <= 31`** 은 바꾸지 못했다. S8 데이터는 **시드 32-39** 이므로
이 검사는 **원리적으로 통과 불가**했다.

## 2. 데이터는 정상이다 (독립 확인)
- 디스크 실측: `data_s8_{crowded,sparse}_2026-08-10` **64 파일**, 시드 집합 = **{32,…,39}** 정확히.
- 같은 게이트의 **다른 모든 검사는 전부 통과**했다:
  G-1 5축 **32종**(양 레짐, 바닥 p **4.66e-10**) · G-1b 길이블록 내 **16/16** ·
  G-1c pooled 64 **전 축 통과** · G-2 메시 ADEQUATE **64/64** · G-3 손잡이 3종 **64/64** ·
  G-4 파일명 교집합 **0**(기존 19집합) · G-5 코드 diff md5 기록 · G-6 신규 게이트 **PASS**.
- ⟹ FAIL 을 만든 유일한 항목이 **낡은 상수 한 줄**이었다.

## 3. 무엇을 고쳤나 — **완화가 아니다**
```python
# 이전 (S7 에서 상속되어 굳음)
24 <= int(seed) <= 31
# 이후 — 상수를 다시 적지 않고 이 배치의 SEEDS 에서 유도한다
got = {seed for e in new}; want = set(SEEDS); seeds_ok = (got == want)
```
- **더 엄격해졌다**: 이전은 구간 포함만 봤고, 지금은 **집합 일치**(빠짐·잉여 둘 다 잡는다).
- **같은 방식으로 다시 낡을 수 없다**(단일 출처 `SEEDS` 에서 유도).
- ⛔**문턱·판정·집계·셀·계측은 한 글자도 바꾸지 않았다.**

## 4. 왜 이것이 사후 완화가 아닌가
1. **S8 결과가 0건**이다. 채점기(`analyze_s8.py`)는 실행된 적이 없고 md5 불변이다.
2. 고친 검사는 **결과와 무관**하다(파일명 시드 확인).
3. 검사가 틀렸다는 것이 **데이터로 증명된다**(디스크 시드 = 32-39 = 사전등록 값).
4. 원본은 `gate_v1_stale.py.bak` 로 보존하고 v1 md5 를 아래 기록한다.

## 5. 대가와 교훈
- **약 3.4시간 유휴**(게이트 FAIL 18:24 → 발견 21:52). 배치는 그동안 돌지 않았다.
- ★**교훈**: `sed` 로 배치 스크립트를 유도할 때 **숫자 상수가 두 번째 자리에 숨어 있으면 따라오지
  않는다.** S7 에서 상속된 `regime()` 이 디렉터리 이름을 하드코딩했던 것(A1)과 **같은 부류의 결함이
  같은 배치에서 두 번째**다. 처방 = **상수를 두 번 적지 말고 한 곳에서 유도**한다(이번에 적용).
- ✅**동시에, 이것은 fail-closed 게이트가 값을 한 사례다** — 게이트가 없었다면 1920런이 돌았을 것이고
  시드 오염 여부는 사후에야 물었을 것이다. 이번엔 데이터가 정상이었지만 **검사가 먼저 멈췄다.**
