## 1. 판정 사다리 교체 (D-1 · D-3)

### 폐기: 옛 `label(w_rescale, w_ship)`
`gates_t11.py` 초판의 `THRESH_LOSE = 13`(= `w ≤ 12`)은 **검정이 아니었다**:

```
P(W ≤ 12 | n=24, q=0.5) = 0.580590      ← 귀무 아래 58% 로 발화
P(W ≥ 17 | n=24, q=0.5) = 0.031957      ← 이쪽만 α=0.05 를 지킨다
⟹ 옛 BEYOND-REACH 는 자료 없이도 0.337(독립)~0.581(완전종속) 확률로 인쇄됐다
```
그런데 `PREREG.md:55` 는 그것을 *"재척도로도 안 된다 ⟹ 대역 말고 다른 것"* 이라는
**양성 주장**으로 정의했다. **두 개의 「기각 실패」로 귀무를 받아들이는 구조**였다.

### 기각한 첫 처방 (기록 — 내가 틀렸다)
*"짐 다리를 `w ≤ 7`(대칭점) 로 올린다"* 를 먼저 제안했다가 **철회했다**. 그렇게 하면
`BAND-MISMATCH = P(Wr≥17) × P(Ws≤7)` 이 되어 **"SHIP 이 유의하게 *더 나쁘다*"** 를 요구한다:
`SHIP` 이 무기술(q=0.5)이어도 `P(Ws≤7) = 0.0320` ⟹ 헤드라인 라벨이 **0.0245** 로 도달 불가.
⛔**이 배치가 묻는 것은 *"SHIP 이 제로필드보다 나쁜가"* 가 아니라 *"SHIP 이 기술을 보이는가"* 다.**
대칭화는 검정력을 고치는 게 아니라 **질문을 바꾼다.**

### 채택: 이김 다리만 검정, 나머지는 **이름으로** 정직화
```python
r_win = w_rescale >= 17          # 유일한 검정 (p = 0.031957)
s_win = w_ship    >= 17          # 유일한 검정
o_win = w_oracle  >= 17          # D-3

 r_win and not s_win  ->  'BAND-MISMATCH'
 r_win and     s_win  ->  'BOTH-WORK'
not r_win and s_win   ->  'RESCALE-HURTS'                      # ★신설
not r_win and not s_win -> 'NEITHER-DETECTED'   if o_win
                           'NO-INFORMATION-IN-OBS' otherwise   # D-3
```
- ★**`RESCALE-HURTS` 신설**: *"재척도가 오히려 해친다"* = 대역가설의 **가장 강한 반증**인데
  옛 사다리는 이 칸을 `UNDECIDED` 로 버렸다(감사 지적).
- ★**`UNDECIDED` 소멸**: 4라벨이 9조합을 **전부** 덮는다(옛 사다리는 6/9 가 `UNDECIDED`).
- ★**음성 라벨 두 개는 이름 자체가 「미검출」이다.** ⛔`NEITHER-DETECTED` 를
  *"도달 불가"*·*"대역 말고 다른 것"* 으로 읽는 것을 **금지**한다. 선례 = `T5-ENS`
  개정문의 *"「검출 불가」이지 폐쇄가 아니다"*.
- **`THRESH_LOSE` 상수를 삭제한다.** 유의 열세(`w ≤ 7`, p=0.031957)는 **라벨이 아니라**
  `verdict['sig_worse']` 에 팔별로 기록만 한다.

### D-3 — `ORACLE` 이 사다리에 들어온다
옛 `label()` 은 `ORACLE` 을 **인자로 받지도 않았다**. ⟹ 음성 결과가 나와도
*"정보가 관측에 애초에 없다"*(자료 탓)와 *"대역 말고 우리 문제"*(우리 탓)를 **구별 못 하는데
라벨 문구는 후자를 단정**했다. 귀속이 목적인 배치에서 귀속의 절반이 사다리 밖이었다.
⟹ 음성 칸을 `o_win` 으로 분기한다.

## 5. `ORACLE` 재정의 (D-2) — **사후 수정 불가라 지금 한다**

초판 `oracle()` 의 중복 제거 키 `(min(i, -i % N0), min(j, -j % N1))` 는 **네 빈**을
한 부류로 접었다: `(i,j)`·`(N0-i,N1-j)`·`(i,N1-j)`·`(N0-i,j)`. 앞의 둘만이 켤레쌍이고
뒤의 둘은 **서로 다른 물리 모드**(±ky 미러)다 ⟹ **두 모드를 하나로 합쳤다.**
실측 확인(32×32, `cos(kx·x+ky·y) + cos(kx·x−ky·y)`): 오라클이 고른 것은 **하나뿐**, 미러 탈락.
게다가 켤레 빈은 파워가 **정확히 같아** `argsort` 타이브레이크가 대표의 부호를 정하는데,
기저가 `cos(k·r − ωt)` 로 ω 부호 고정이라 반대 부호가 뽑히면 그 기저는 **역진행파**
= 창 전체에서 참 모드와 직교하는 **죽은 기저**다.

⟹ ⛔**초판 `ORACLE` 은 「정보 존재의 상한」이 아니라 하한이었다.** 양성 SEC-B 는 보수적이라
유효하지만 **널 SEC-B 는 해석 불가**(*"정보 없음"* vs *"오라클이 반쪽"*)가 된다.

### 채택
1. 정준키를 **켤레쌍만** 접도록 고친다: `key = min((i,j), ((N0-i)%N0, (N1-j)%N1))`.
2. 모드마다 **`±ω` 네 열**(`cos(θ⁻), sin(θ⁻), cos(θ⁺), sin(θ⁺)`, `θ∓ = k·r ∓ ωt`)을 넣어
   진행 방향을 자료가 고르게 한다. 여전히 *"참 파수에서 A,φ 만 LS"* 이다.
3. `nmode` 를 `gates_t11.py` 상수로 올린다(초판은 러너 지역 리터럴 100 이었다).

## 9. ⚠**스모크 후 게이트 변경 2건 — 공시** (⛔결과 0행 · 프리즌 표본 미접촉)

이 개정문의 게이트를 **노출된 감사 파일 2개**로 스모크한 결과 두 가지가 드러났다.
저장소 규율이 *"⛔사후 완화 금지"* 이므로 **무엇을 왜 고쳤는지 여기 박는다**
(선례 = `M4` 의 *"`G-15` 사후 완화 + 검사기 자기동결 공시 병기"*).

### 9.1 ★`G-CLAMP` 를 **비차단(기록)** 으로 바꿨다 — §6c 의 예측이 **반증됐다**

§6c 는 *"z 를 재척도하지 않아 파고경사가 2배 ⟹ `hs_high` 에서 **`RESCALE` 만**
`clamp_steepness(0.15)` 에 닿을 수 있다"* 라 적었다. 스모크 실측은 **정반대**다:

| 블록 | Hs | `SHIP` 발화 | `RESCALE` 발화 |
|---|---|---|---|
| `mixed_data2/angle10h0.5.mat` | 0.5 | **1** | 0 |
| `mixed_data2/angle10h2.0.mat` | 2.0 | **2** | 0 |

기제: 클램프는 **자료의 경사**가 아니라 **적합된 모델 원자**에 작용하는데 두 팔이 서로
다른 원자를 설치한다(`SHIP` 26·30개 vs `RESCALE` 8·25개). ⟹ *"경사가 2배니까 RESCALE 이
걸린다"* 는 **그 값이 들어가는 양에서 한 예측**이었고, **판정에서 재니 뒤집혔다.**
★저장소 상시 교훈의 재현: ***개입·오류의 효과를 그것이 들어가는 양에서 재지 말고
판정에서 재라*** (`B-2` 수심 17→30 사건과 같은 부류).

**변경**: 클램프는 **출하 추정기의 정상 동작**이다(`varpro.py:243-246` 이 항상 돈다).
발화로 배치를 막는 것은 *"출하 팔이 특정하게 동작해야 한다"* 는 요구이지 측정 타당성의
게이트가 아니다. ⟹ **차단 조건은 「되읽기 부재」로 좁히고**, 발화 자체는
`verdict['clamp_hits_by_arm']` 과 공시로 남긴다.
⟹ ✅**§6c 의 걱정(「RESCALE 이 클램프로 이득을 본다」)은 죽었다** — `RESCALE` 은 0회다.
⚠**대신 새 비대칭이 공시된다**: `SHIP` 만 클램프에 닿는다. ⛔이것을 성능 차의 **원인으로
지목하지 마라** — 방향도 크기도 측정하지 않았다.

### 9.2 `G-TORIGIN` 회귀 수리 (내 버그)
개정 러너가 `ZERO`·`ORACLE` 행에서 `t_origin` 키를 **떨어뜨렸다** ⟹ 4/8 행이 `None` 으로
위반 처리됐다. 관측 배열에서 되읽도록(`float(tt.min())`) 고쳤다.
★**게이트가 러너의 회귀를 잡았다** — 그게 게이트가 있는 이유다.

### 9.3 부수 수리
- `sig_worse`(`w ≤ 7`)를 **`n == 24` 일 때만** 판정한다. 작은 `n` 에서는 자동으로 `True` 가
  되어 **항진**이다(스모크 n=2 에서 세 팔 모두 `True` 로 찍혔다).
- 분석기의 `verdict` 출력 경로만 `OUTDIR` 로 분리했다 — 스모크 하네스가 `HERE` 를 흔들면
  선행 배치 참조 경로까지 깨져 **가짜 FAIL** 이 났다.

### 9.4 ★`ORACLE` 재정의의 효과가 스모크에서 즉시 드러났다
같은 두 파일에서 `ORACLE` nRMSE 가 **0.2242 → 0.1324** · **0.1998 → 0.1565** 로 떨어졌다.
⟹ 초판 오라클은 `ZERO`(0.2287·0.2348)를 **간신히** 넘고 있었다. 그대로 갔다면 `SEC-B` 가
널에 가깝게 나와 **`NO-INFORMATION-IN-OBS`**(= *"정보가 관측에 없다"*)라는 **거짓 라벨**이
인쇄될 수 있었다. ⛔이 두 파일은 노출 표본이므로 **크기를 결과로 인용하지 마라** —
여기서의 요점은 크기가 아니라 **결함이 실재했다**는 것이다.
