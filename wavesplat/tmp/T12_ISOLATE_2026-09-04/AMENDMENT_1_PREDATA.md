# `T12-ISOLATE` 개정문 1 — **결과 0행** (프리즌 표본 24·28 미접촉)

작성: 2026-09-04. `results_t12.jsonl` **없음** · `verdict_t12.json` **없음**.
스모크(노출된 감사 파일 2개 × 13팔 = 26행)가 세 가지를 드러냈다. ⛔전부 **결과 전** 수리다.

## 1. `G-EFFECT` 의 범위 — 사전등록 표가 **자기모순**이었다

`PREREG.md §6` 의 `G-EFFECT` 행은 통과조건 열에 *"각 처치 팔이 SHIP 과 비트 동일한 행이
24/24 는 아니다"* 라 적고, 같은 칸에 *"⟹ 그러면 **`NO-OP` 로 보고**(널 아님)"* 라 적었다.
**차단되면 보고할 verdict 자체가 없다** ⟹ 두 조항이 양립하지 않는다.

**해소(결과 전)**: 차단은 **`PRIMARY` 팔에 대해서만**. `SEC` 팔이 no-op 이면 배치를 막지 않고
`verdict['no_op_arms']` 에 기록하고 그 팔을 **`NO-OP`(널 아님)** 으로 보고한다.
★사유: SEC 팔 하나가 지렛대가 없다고 배치 전체를 막는 것은 *"도달 불가"* 와 *"지렛대 부족"* 을
섞는 것이다(`LEARNED_AUDIT_2026-08-30` 규율). 그리고 `PRIMARY` 가 no-op 이면 이 배치는
**질문에 답하지 못하므로** 그때는 막는 것이 옳다.
⚠스모크 실측: `C-MINDK` 가 2/2 블록에서 `SHIP` 과 **비트 동일**했다(성장은 2/2 발화했는데도).
본실행 n=24 에서 다시 볼 값이다.

## 2. ⛔`G-KNOB` 의 되읽기 지점이 **구조적으로 눈이 멀었다** — 되읽기를 바꾼다

`PREREG.md §6` 이 조건화 맵 상태의 되읽기로 **`OM_G[0,0].item()`** 을 지정했다.
그런데 그 칸은 격자 **모서리**(`k = |(-0.6,-0.6)| = 0.8485`)이고, 실측:
```
k=0.8485   tanh(k·50) = 1.000000     tanh(k·400) = 1.000000     차이 = 0.000e+00
k=0.0301   tanh(k·50) = 0.906199     tanh(k·400) = 1.000000     차이 = 9.380e-02
```
⟹ **심해 포화 때문에 모서리에서는 수심 변화가 `float32` 로 정확히 0 이다.**
스모크에서 `E-MAPDEPTH` 가 `OM_G` 를 실제로 바꿨는데도 `G-KNOB` 이 *"안 바뀌었다"* 로 읽고
**위반 2건**을 냈다. 전체 텐서 md5 는 **바뀐다**(직접 확인).

**해소(결과 전)**: `OM_G00`(한 칸) → **`OM_Gmd5`(전체 텐서 지문)**.
★이것은 **완화가 아니라 강화**다 — 한 칸이 아니라 4,096칸 전부를 본다.
★★교훈: ***되읽기 지점을 효과가 구조적으로 보이지 않는 곳에 두면, 개입이 걸렸는데도
「안 걸렸다」로 읽힌다.*** `T11 AMENDMENT_2 §9.1`(클램프 예측 반증)과 `B-2`(수심 17→30)의
거울상이다 — 그 둘은 *"효과를 그 값이 들어가는 양에서 쟀다"* 였고, 이번은
*"효과가 죽는 지점에서 쟀다"* 다. 처방은 같다: **판정에서 재라.**

## 3. 구현 결함 — `deployed()` 의 키 이름이 `KNOB_KEYS` 와 어긋났다

`consts_t12.deployed()` 가 `KX_G00`·`OM_G00`·`vp_lr` 을 **내놓지 않았다**(마지막 것은
`VP_LR_DEFAULT` 라는 다른 이름으로 있었다). 분석기의 비교는 `dep.get(k) is None` 이면
**그 키를 조용히 건너뛴다** ⟹ 세 키가 비교에서 빠졌다.
⟹ ⛔`D-VPLR` 의 측정된 노브 차이가 **빈 집합**으로 나왔다 — 즉 ***이 배치가 잡으려던 바로 그
「조용한 no-op」을, 게이트 자신이 조용히 놓치고 있었다.*** 수리 후 `['vp_lr']` 로 발화한다.
★설계 결함이 아니라 **키 이름 불일치**다. 그러나 결과는 같다 — **비교에서 빠진 키는 항상 통과한다.**
⟹ 처방으로 `G-KNOB` 은 이제 **문자열 지문도** 비교하고, 키 부재는 `G-RESTORE` 가 위반으로 잡는다.

## 4. ✅`PREREG.md §2.5` 의 GPU 재현성 분기 — **판정: 차단 게이트 유지**

같은 블록(`Data/mixed_data2/angle10h0.5.mat`)에서 `SHIP` 을 두 번 돌렸다:
```
시행 1: nrmse=0.2281773589  proposal_md5=28fc7b8e63b305a6…
시행 2: nrmse=0.2281773589  proposal_md5=28fc7b8e63b305a6…
⟹ GPU 제안이 **비트 재현**된다
```
⟹ **`G-PROPID` 는 차단 게이트다**(강등하지 않는다). `meta['propid_blocking'] = True`.
★부수 확인: 이 `proposal_md5` 는 `T11` 스모크가 같은 블록·같은 시드에서 기록한 값과 **일치**한다
⟹ 팔을 9개 더해도 제안 경로가 흔들리지 않는다는 첫 신호(`G-ANCHOR` 는 본실행에서 판정).
