### §1.1 ★핵심 난점을 먼저 — 처치가 한 문제를 고치고 다른 문제를 만든다
맵을 d=400 으로 바꾸면 **자료-맵 정합**(defocus 제거)은 회복되지만, 넷은 **d=50 맵으로 학습**됐으므로 이번엔
**학습/추론 불일치**가 생긴다. 그 크기를 코드 상수로 추정하면(⚠추정이지 측정이 아니다 — 그래서 §4 에 `FIX-HURTS` 다리를 둔다):
- 넷 입력은 64×64 로그정규화 파워맵뿐이다(`d3_beamform_cond_diffusion.py:44-56 CondEncoder`). 정합 맵에서 봉우리 **위치**(kx,ky)는 수심과 무관.
  수심이 바꾸는 것은 시간 디포커스가 만드는 **방사 방향 PSF 폭**뿐이고 그것은 군속도 비로 스케일된다:
  `cg(d=400)/cg(d=50)` = **0.739 (k=0.02) · 0.809 (0.03) · 0.888 (0.04) · 0.974 (0.06)** ⟹ 방사 폭 ×1.13–1.35.
- 학습 밴드는 `Tp∈U(5,11)` ⟹ `k_p` 0.035–0.161, `kd` 1.76–8.05, `tanh` 0.943–1.000 — 넷은 이미 **cg 가 2.6배 갈리는** PSF 폭을 보았다.
- 반면 **이미 존재하고 이 배치가 건드리지 않는** 불일치가 더 크다: 개구/픽셀 비(T11 A2 §6a) — 조건화 맵 PSF **0.53칸**(T11) vs 학습 **1.37–1.65칸** = ×2.6–3.1.
⟹ 예측: 불일치 대가 < defocus 이득. **단 이것을 가정하지 않고 잰다**(§4 의 HURTS 다리 + §2 의 음성대조 `RESCALE-FIX`).

## §4 결정표 (결과 전 고정) — 이김 다리만 검정, 음성은 **이름이 「미검출」**

부호검정 α=0.05 **단측**, 짝 = 같은 파일(같은 관측·시드). 통계량 `w` = 처치가 기준보다 **낮은** `nRMSE` 를 낸 파일 수.

| 검정 | 비교 | n | 임계(유일한 검정) | p |
|---|---|---|---|---|
| **PRIMARY** | `FIX < SHIP` | **52** | `w ≥ 33` | 0.0352 |
| PRIMARY-HURTS 다리 | `FIX > SHIP` | 52 | `w ≤ 19` | 0.0352 |
| **SEC-A** | `FIX < ZERO` | 52 | `w ≥ 33` | 0.0352 |
| CTRL(음성대조) | `RESCALE-FIX` vs `RESCALE` | 24 | ⛔검정 아님 — `w∈[8,16]` 예상(귀무 하 0.936) + 크기 바닥 | — |
| 기술통계 | 층 `T11-24`(임계 17) · `FRESH-28`(임계 19) · Hs<2/≥2 · `ORACLE<ZERO`(FRESH-28) · `SHIP<ZERO`(52) | | ⛔라벨 없음 | 무보정 |

⚠**HURTS 다리를 라벨로 둔 이유**(T11 A2 §1 은 `w≤7` 을 라벨로 거부했다): T11 의 질문은 *"SHIP 이 기술을 보이는가"* 라 대칭화가 질문을 바꿨다.
T13 의 질문은 §1.1 그대로 **양방향**이다 — 처치가 **해칠 수 있다는 것이 설계의 전제**이므로 「유의하게 나쁘다」가 실질 결과다.
두 다리의 가족 α = **0.0704**(0.0352×2) — 공시하고 보정하지 않는다.

### 라벨 사다리 (PRIMARY × SEC-A · 9조합 → 5라벨, `UNDECIDED` 없음)
```python
helps = w_fix_ship >= 33 ; hurts = w_fix_ship <= 19 ; skill = w_fix_zero >= 33
hurts                    -> 'FIX-HURTS'                     # 불일치 대가 > defocus 이득 (§1.1 의 반대 방향)
helps and skill          -> 'DEPTH-WAS-MASKING-SKILL'       # 결함이 기술을 가리고 있었다 (T11 SEC-A 의 일부가 결함 귀속)
helps and not skill      -> 'FIX-HELPS-NO-SKILL'            # 교락은 이빨이 있으나 대역 실패는 남는다
not helps, not hurts, skill      -> 'SKILL-FIX-UNDETECTED'  # 기술은 보이는데 처치 효과는 미검출 (⚠약한 칸 — 해석 §11)
not helps, not hurts, not skill  -> 'FIX-UNDETECTED'        # ★미검출 — MDE 병기 의무
```
- ⛔`FIX-UNDETECTED` 를 *"수심은 원인이 아니다"*·*"교락은 무해하다"* 로 읽지 않는다. 그것은 **검정력의 진술**이다(§6 `q80` 병기).
- ⛔`DEPTH-WAS-MASKING-SKILL` 을 *"T11 `BAND-MISMATCH` 철회"* 로 읽지 않는다 — T11 의 라벨은 `RESCALE ≥17` **과** `SHIP <17` 이고 이 배치는 `RESCALE` 대 `FIX` 를 검정하지 않는다.
  T11 라벨의 **재판정**은 `FIX` 를 T11 사다리의 `SHIP` 자리에 넣어 **기술통계로만** 인쇄한다(`T11-24` 층, 임계 17, ⛔라벨 아님).
- CTRL 읽기(결과 전 고정): `floor = median|relΔ|(RESCALE-FIX vs RESCALE)`, `effect = median relΔ(FIX vs SHIP)`, 둘을 **나란히** 인쇄.
  `|effect| ≤ floor` 이면 PRIMARY 라벨에 접미 **`(WITHIN-PERTURBATION-FLOOR)`** 를 붙인다 — 라벨을 바꾸지 않고 읽기를 좁힌다.
  CTRL 의 `w` 가 `[8,16]` 밖이면 `verdict['ctrl_moved']=True` 로 공시(⛔기제 지목 금지 — 방향·크기를 이 배치가 설계하지 않았다).

## §5 사전등록 예측 (명시 고정) 과 라벨별 확률

## §11 ⛔범위와 금지

- ⛔**배포 권고 아님.** `FIX` 는 **하네스 처치**다(패키지에 없다). 이기더라도 배포는 (i) 패키지 수리(`REACHABILITY §5` 형태) (ii) `test_shipping_defaults` 핀 갱신
  (iii) 배포-후 게이트 출력 첨부(08-23 교훈 *"측정한 구성 ≠ 배포한 구성"*) 가 있는 **별도 결정**이다.
  ★단 그 수리는 자국 합성 코퍼스(110 에피소드 전부 d=50)에서 **비트 무연산**이므로 기존 판정의 재확증은 요구하지 않는다 — 그 사실도 배포 결정문이 다시 실측해야 한다.
- ⛔`FIX` 의 절대 `nRMSE` 를 성능으로 인용 금지 — 읽는 것은 **짝 부호와 상대 크기**뿐이다.
- ⛔`DEPTH-WAS-MASKING-SKILL` 을 *"BAND-MISMATCH 철회"* 로 읽기 금지(§4). T11 사다리 재판정은 기술통계다.
- ⛔`FIX-HURTS` 를 *"학습/추론 불일치가 원인"* 으로 **지목** 금지 — 이 배치는 불일치의 크기를 재지 않는다(§1.1 은 추정). 허용 = *"맵 수심을 자료에 맞추는 것만으로는 배포 체크포인트에서 해가 된다"*.
- ⛔`SKILL-FIX-UNDETECTED` 는 약한 칸이다 — `FIX<ZERO` 유의인데 `FIX<SHIP` 미검출이면 `SHIP<ZERO` 도 함께 인쇄해 **두 팔 다 기술 문턱 근처**임을 보인다(`F1` 부류 경고).
- ⛔`FRESH-28` 층의 Hs 치우침(25/28 ≥ 2.0)을 *"높은 해상에서 처치가 …"* 로 읽기 금지 — 층은 라벨을 만들지 않는다.
- ⛔`RESCALE` 대비 `FIX` 를 검정하지 않는다(다요인, A2 §6a). 인쇄만.
- ⛔`wall_s` 팔 간 비교 금지(BLAS 스레드 · T11 공시).
- ⚠`Tp` 전 파일 10 s ⟹ 한 주기 조건의 진술(T11 과 동일).
- ⚠재학습(처치 3)은 **미측정**으로 남는다 — 이 배치가 `FIX-HELPS-*` 를 내면 재학습의 사전등록 동기가 되고, `FIX-HURTS` 를 내면 *"맵만 고치면 된다"* 가 죽는다. 어느 쪽도 재학습의 결과를 예단하지 않는다.
