## 1. ⛔⛔`G-ENV` 가 **거짓을 인쇄하고 있었다**

초판:
```python
live = meta.get('code_md5_now') or rec     # ← 대입만 되고 **한 번도 쓰이지 않는다**
dm = sorted(k for k in set(rec)|set(fz) if fz.get(k) != rec.get(k))   # 기록된 스냅샷 둘끼리
```
⟹ **어디서도 md5 를 「지금」 다시 계산하지 않는다.** 그래서 `AMENDMENT_2` 가 런 **뒤에**
`analyze_t14.py` 를 고쳤는데도 게이트가 **"동결드리프트 0"** 을 찍었다 —
***verdict 을 만든 분석기가 동결된 그 파일이 아닌데도.***
실측: 라이브 `analyze_t14.py` md5 = `b11e14ae…` · `meta['code_md5']` = `FROZEN_md5.txt` = `74c37c0c…`.

그리고 `AMENDMENT_2 §4` 가 만든 **`FROZEN_md5_A2.txt` 를 읽는 코드가 0개**였다(`grep` 0 hit).
⟹ ***파일만 만들고 검사기를 안 붙였다*** = 저장소가 *"「동결한 적이 없다」가 「동결 뒤에
움직였다」보다 나쁘다 — 구조적으로 탐지 불가"* 라 부르는 바로 그 부류.
⚠**`T13 AMENDMENT_2 §2` 가 하루 전에 세운 측정면/분석면 분리를 이 배치가 계승하지 않았다.**
`analyze_t12.py:225`·`analyze_t13.py:208` 은 둘 다 `freeze_map()` 을 **지금** 다시 돈다. T14 만 후퇴했다.

**해소**: `run_t14.freeze_map()` 을 분석 시점에 호출하고, **측정면**(현재==meta==`FROZEN_md5.txt`)과
**분석면**(현재==`FROZEN_md5_A2.txt`)을 갈라 대조한다. 삭제도 잡도록 **합집합**으로 돈다.
⟹ 이제 이 개정문이 분석기를 고쳤으므로 `FROZEN_md5_A2.txt` 를 **다시** 동결해야 게이트가 통과한다.
★그것이 요점이다 — **고치면 게이트가 알아야 한다.**

## 2. ⛔Tier-2 스윕 36런이 **0행 비교**를 냈다 — 배치 계산량의 약 20%가 무산출

```python
sw = {a: wins(a, 'ZERO', 'T2') for a in G.T2_ARMS}   # ⛔Tier-2 는 ZERO 를 안 돌린다
```
`run_t14.py:158` 이 Tier-2 를 `T2_ARMS`(SW-* 셋)만 돌리므로 `by[('T2','ZERO')]` 가 **없다**
⟹ `wins()` 가 빈 dict 와 교집합해 전부 `(0,0)`. 인쇄된 값:
`{'SW-1.414': [0,0], 'SW-2.828': [0,0], 'SW-4.000': [0,0]}`.

★**무게**: 이 배치의 **공시 3번**이 축자로 적었다 —
*"이 설계는 두 규칙 중 어느 쪽인지 구별하지 못한다 … **판별은 스윕(기술통계)의 몫이다**."*
⟹ ***그 판별자가 통째로 비어 있었다.***

**해소**: Tier-2 는 Tier-1 의 **부분집합**이므로(`gates_t14.tiers()`, 실측 `subset=True`) 참조
`ZERO` 는 `('T1','ZERO')` 에 그대로 있다. 올바른 짝으로 재계산한다. **새 런 0회.**
⚠스윕은 **기술통계**이고 라벨을 만들지 않는다 — 그리고 이 배치는 `BLOCKED` 라 어차피 라벨이 없다.
⛔**그리고 스윕을 규칙의 증거로 쓰지 마라**(사전등록 §1: `SW-2.828` 이 `s_ap≈2.81` 과 0.7% 차로
**우연히** 겹친다 — √2 격자는 스케일-자유라서 골랐지 규칙에서 유도하지 않았다).
