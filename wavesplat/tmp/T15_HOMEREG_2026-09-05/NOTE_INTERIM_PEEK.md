# ⚠`T15` — **내가 본실행 도중 PRIMARY 통계량의 중간집계를 봤다** (공시)

시점: 본실행 `FULL` 샤드 **30/128 블록** 진행 중(혼잡 층만 존재). 이 파일은 그 시점에 쓰였고,
`results_t15_FULL.jsonl` 이 **미완성**인 상태로 커밋된다 — git 순서가 그것을 증명한다.

## 무엇을 봤나 (⛔전부 적는다)
```
혼잡 30블록 중간집계
   F2 < SHIP            14/30      (PRIMARY 통계량 — 문턱은 n=64 의 23/41)
   SHIP < ZERO          29/30      (양성대조)
   FLOOR-VPLR < SHIP    16/30      (잡음 바닥, 라벨 아님)
```

## 왜 문제가 아닌가 (⛔그러나 왜 그래도 적는가)
- **선택적 정지가 없다.** 표본은 사전등록에 128 로 못박혀 있고 러너는 목록을 끝까지 돈다.
  중간에 멈출 경로가 코드에 없다.
- **분석기가 동결돼 있다.** 문턱·사다리·등가 규칙·MDE 는 `FROZEN_md5.txt`(측정면 25키)와
  `FROZEN_md5_ANALYSIS.txt` 가 잡고 있고 `G-ENV` 가 3중 대조한다.
  ⟹ **내가 무엇을 봤든 판정을 바꿀 기제가 없다.**
- ⛔그럼에도 저장소 규율은 *"집계·방향·MDE 를 결과 전에 동결"* 이고, **본 것을 안 적는 것**이
  이 저장소가 반복해서 대가를 치른 부류다(`T5-ENS` 미공시 노출 · `T12` blind 자구 사고).
  ⟹ 크기가 아니라 **습관**의 문제로 적는다.

## 이후 규칙 (스스로에게)
본실행이 끝날 때까지 **PRIMARY·부차 통계량을 다시 집계하지 않는다.**
로그 감시는 **진행률과 오류 문자열**만 본다(`✅`·`Traceback`·`Killed`·`Error`).

## ⚠부수 관찰 (⛔라벨 아님)
중간집계의 방향은 **스모크 2블록이 시사한 것과도, 내 등록 예측과도 다르다**
(스모크는 혼잡에서 `F2` 압승, 등록 예측은 `F2` 패배, 30블록 중간은 거의 동전던지기).
⟹ ★**n=2 로 방향을 읽으면 안 된다**는 것의 실물 예다. `AMENDMENT_1_PREDATA.md §1.3` 이
*"크기는 논거가 아니다"* 라 적은 바로 그 자리에서, **크기가 실제로 작았다**.
⛔단 30/128 도 여전히 부분집계다 — 이 문단에서 어떤 결론도 끌어내지 마라.
