## 1. 무엇이 잘못돼 있었나 — ★**구조적으로 항상 실패하는 게이트**

동결 직전 `run_t2.py selftest` 가 잡았다. 원래 `G-7b` 는 이랬다:

```python
A(('G-7b <토큰> 상수 부재', not any(
    '<토큰>' in open(os.path.join(HERE, f), ...).read()
    for f in os.listdir(HERE) if f.endswith('.py')), ''))
```

⛔**금지문 자신이 그 토큰을 담는다.** `gates_t2.py` 는 그 토큰을 산문으로 **4회**
(§2 제목 · 독스트링 · 게이트 이름), `run_t2.py` 는 2회 담고 있었다.
⟹ `any(...)` 가 **항상 참** ⟹ `G-7b` 가 **항상 실패** ⟹ `analyze()` 의
`label = None if blocked else …` 규칙에 따라 ***이 배치는 어떤 자료로도 라벨을 낼 수 없었다.***

실측(수리 전): `G-7b as written would evaluate to: False` ·
`gates_t2.py: 4회 · premise_t2.py: 0회 · run_t2.py: 2회`.

## 2. ★이 결함의 부류

`M-8` 의 `G-ANCHOR-B` 와 같은 「차단 게이트」로 **보이지만 더 나쁘다**:
`G-ANCHOR-B` 는 **자료의 결함**을 잡은 참된 실패였고, 이것은 **자료와 무관하게** 실패한다.
저장소가 이미 이름 붙인 부류다 — ***"검사기가 검사하지 않는다"*** 의 극단형:
**통과할 수 없는 검사기는 검사기가 아니라 차단기다.**

★그리고 이것이 **144런 뒤에 발견됐다면** 선택지가 둘뿐이었다 —
①라벨 없이 닫는다(자료 낭비 + 실측 게이트 1회 소모) ②결과를 본 뒤 게이트를 고친다(= `M-4` 의 죄).
⟹ ***형이 세운 「긴 배치 전에 몇 케이스 돌려봐라」 규칙이 이번에는 코드 자가진단 단계에서 값을 했다.***

## 3. 수리

문자열 검색 → **`ast` 판정**으로 교체했다(`gates_t2._no_flat_ref_constant`).
독스트링·주석의 **산문은 통과**시키고 `ast.Name`/`ast.Attribute` 로 **실제 사용만** 잡는다.
토큰 자체는 `_FLAT_NAME = 'ZERO' + '_REF'` 로 조립해 소스에 리터럴로 두지 않는다.

★**그리고 항진 검사를 붙였다** — `gates_t2.selftest()` 가
①현 상태에서 통과하고 ②위조 파일(`_g7b_probe.py`, 그 이름을 **코드로** 쓰는 파일)을 넣으면
**반드시 실패**함을 확인한다. ⛔*"통과했다"* 가 *"검사했다"* 를 뜻하지 않는다는 것이
이 저장소가 세 번 대가를 치른 교훈이다.

`run_t2.py` 의 사전 확인 [7] 은 **자기 구현을 갖지 않고** `gates_t2._no_flat_ref_constant()` 를
호출한다(⛔같은 기능을 두 곳에 구현해 한쪽만 계측하는 것이 이 저장소의 반복 결함 3부류 중 하나).

## 4. 바뀌지 않은 것

- **팔 · 문턱 · 표본 · 라벨 · 해석 규칙 · 방향 · 금지 목록 — 전부 무수정.**
- `G-7b` 의 **의도도 무수정**: *"이 배치는 고정 기준상수로 채점하지 않는다"*.
  바뀐 것은 **그 의도를 실제로 검사하게 만든 것**뿐이다(전에는 검사한 적이 없다 — 항상 실패했으므로).
- 다른 게이트 전건 무수정.
