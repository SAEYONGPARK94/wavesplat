# ⚠4샤드 분할로 시작했다가 **판정 전에 중단**한 행 (2026-08-31 00:30)

70행(`SHIP` 66 · `SPEC25` 4). ⛔**판정에 쓰지 않는다.**

## 사유 — 자료 결함이 아니라 **샤드 재배정**

`cells()` 가 팔-마이너 순서라 `i % 4` 가 곧 팔 인덱스다 ⟹ 4샤드는 비싼 `SPEC25` 를
샤드 1·3 에 **몰아넣는다**(실측 `SHIP` 0.52 코어·h vs `SPEC25` 4.85).
투영: **4샤드 ≈ 2.4 h · 3샤드 ≈ 1.79 h**(총 코어·h 는 5.36 으로 **동일**).
⟹ 3샤드로 재시작했다. 같은 셀이 **다른 샤드 파일에 재배정**되므로 이 행들을 남겨 두면
셀이 중복 적재돼 `G-1` 이 실패한다.

## ⛔이것은 자료의 결함이 아니다

행 자체는 유효했다 — 에러 0 · 앵커 `relΔ = 0.0e+00`(비트) · 음성대조 `True` ·
양성대조 `7.2e-15`. **분할 정책만 바꿨고 코드·팔·문턱·행 스키마는 무수정**이다
(`run_t4.py` md5 불변 — 본런 중 러너를 고치면 `G-10` 단일 스탬프가 깨진다는
러너 작성자의 경고를 지켰다).
⟹ 재시작본이 같은 셀을 다시 계산하며 **값은 비트 동일해야 한다**.

## ★교훈 (형의 상시 규칙에 붙는다)

*"긴 배치 전에 스모크"* 는 **단가**를 잡아 줬지만 **샤드 균형**은 못 잡았다.
⟹ ★**스모크가 팔별 단가를 내면, 본런 전에 「샤드별 부하」를 계산해 보라.**
`cells()` 의 순서와 샤드 수가 **약수 관계**면 비싼 팔이 한 샤드에 몰린다
(`T3` 도 같은 이유로 4·8샤드가 11.3배 불균형이었고 6샤드를 골랐다).
