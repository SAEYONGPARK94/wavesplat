# PREREG — `T6-BUDGET` : 배포 **학습 경로**의 프레임 예산

**동결 시각에 결과 행 0개.** 이 문서가 동결된 뒤에는 한 글자도 고치지 않는다.
고쳐야 할 일이 생기면 `AMENDMENT_*.md` 를 **결과를 보기 전에** 따로 쓴다.

## 0. 왜 이 배치인가 (두 감사가 같은 것을 가리켰다)

- **심사자 감사(2026-09-02)** MAJOR #3 축자: *"For a real-time method in this venue,
  **one wall-clock table is not optional**."* 논문은 실시간을 네 번 말하면서 지연을
  전부 철회했고, §복잡도는 *"배포 초기화 비용은 특성화되지 않았고 **측정이 없다**"* 고 적는다.
- **설계 감사(2026-09-02)** 축자: *"the cheapest batch in the repo that moves a real-time
  claim from absent to measured."* 새 코퍼스 불필요 · 생성 0회 · 시간 단위.

⟹ ★**이 배치는 정확도를 재지 않는다.** 팔간 정확도 비교는 한 줄도 하지 않는다.

## 1. 무엇을 재는가

동일 프로세스 · **1 스레드** · 단조 시계(`perf_counter`) 로:

| 양 | 정의 |
|---|---|
| `init_s` | `updater.initialize(init_window)` 벽시계 초 |
| `frame_ms` | `updater.update(frame)` 벽시계 ms, 추적 프레임 **전건** |
| `budget_frac` | `median(frame_ms) / 100 ms` (10 Hz 프레임 예산 대비) |

## 2. 설계 (2 × 2 × 2)

| 인자 | 수준 |
|---|---|
| **장치** | `GPU`(가용) · `CPU`(`CUDA_VISIBLE_DEVICES=''`) |
| **경로** | `LEARN` = 출하 기본값(`init_method='auto'` ⟹ 라우터가 `learned` 로 해소) · `ANA` = `init_method='v2_konly'` |
| **층** | `crowded`(BF4/BF5 15·30성분) · `sparse` |

에피소드: 층당 **8개**, 시드 42 고정 ⟹ **64 런**.
⛔`{}` 로 팔을 정의하지 않는다 — 두 팔 다 `dict(DEFAULT_CONFIG)` 에서 시작하고
`init_method` **하나만** 다르다(단일요인).

## 3. 사전 고정 — 읽기 규칙

### PRIMARY (인용 대상)
> **배포 학습 경로의 프레임당 추적 비용(중앙값, 1스레드, 동일 프로세스)과
> 그것이 10 Hz 예산에서 차지하는 비율.**

층별로 따로 보고한다. ⛔층을 합산하지 않는다.

### SECONDARY
> 일회성 초기화 비용(`LEARN` vs `ANA`, 장치별).

### ⛔주장하지 않는 것 (결과 전 고정)
1. ⛔**정확도 주장 0건.** 이 배치의 어떤 수도 정확도 비교에 쓰지 않는다.
2. ⛔**철회된 프로세스간 수치**(13.4 ms · 132.6 ms)와 **비교 금지**. 다른 양이다.
3. ⛔**기준선(LETKF/ETKF) 지연과 비교 금지** — 이 배치는 기준선을 돌리지 않는다.
4. ⛔*"실시간이다"* 라고 쓰지 않는다. 쓸 수 있는 것은 **측정된 비율**뿐이고,
   그 비율은 **초기화를 포함하지 않는다**(초기화는 일회성이고 따로 보고한다).
5. ⛔**렌더 비용**(`B-6b`, 137 µs/점)과 **합산 금지** — 그것은 질의 쪽이고 팔이 다르다.
6. ⛔실측 레코드로 **전이 금지**(실측은 다른 경로 = `bank_mmse`).

### ⚠결과 전에 아는 것 (노출 공시)
스모크 2셀(혼잡 1에피소드, 두 경로 × 두 장치)을 **이 문서 동결 전에** 돌렸고
그 값을 봤다. ⟹ ★**이 배치는 blind 가 아니다.** 스모크 셀은 본 배치에 포함되며
따로 표시한다. 스모크가 보여준 것: 학습 초기화가 해석적보다 빨랐고, CPU/GPU 차이가
작았으며, 프레임 비용이 예산의 10% 미만이었다. **본 배치는 그 세 방향을 8에피소드 ×
2층으로 확인하거나 반증한다.**

## 4. 차단 게이트 (하나라도 실패하면 라벨 없음)

| # | 게이트 | 판정 |
|---|---|---|
| `G-1` | `torch.get_num_threads() == 1` **전 행** | 아니면 지연이 비교 불가 |
| `G-2` | `cuda_available` 이 요청 장치와 일치 **전 행** | CPU 팔에서 True 면 무효 |
| `G-3` | **경로 되읽기**가 기대와 일치 (`LEARN`→`learned`, `ANA`→`v2_konly`) — ⛔의도표가 아니라 **객체 속성** | 라우터가 다른 데로 갔으면 무효 |
| `G-4` | 한 샤드 = 한 PID, 전 행 동일 | 프로세스간 비교가 되면 금지 수치와 같은 결함 |
| `G-5` | **시계 교정**: `perf_counter` 로 잰 `sleep(0.05)` 가 50–55 ms | 시계·부하 확인 |
| `G-6` | 같은 에피소드에서 두 경로의 **추적 프레임 수 동일** | 프레임 불일치는 이 저장소의 원죄다 |
| `G-7` | 배포 상수 되읽기 (`lambda_l1`·`varpro_steps`·`tracking_steps`·`tracking_window`·`tracking_mode`) 가 출하값 | 다른 구성의 예산은 배포 예산이 아니다 |
| `G-8` | 행 수 == 64, 결측 0 | |
| `G-9` | `init_s > 0` 이고 `frame_ms` 전건 유한·양수 | |
| `G-10` | **부하 상한**: 각 행의 프레임 p95/중앙 비 ≤ 3.0 | 경합 중 측정은 인용 불가 |

## 5. 라벨 결정표 (결과 전 고정)

`m` = 배포 학습 경로의 프레임 중앙 (혼잡 층, CPU 팔 — **가장 보수적인 칸**).

| 조건 | 라벨 |
|---|---|
| `m ≤ 10 ms` (예산의 10% 이하) | `FRAME-BUDGET-AMPLE` |
| `10 < m ≤ 50 ms` | `FRAME-BUDGET-FITS` |
| `50 < m ≤ 100 ms` | `FRAME-BUDGET-TIGHT` |
| `m > 100 ms` | `FRAME-BUDGET-EXCEEDED` |

⚠라벨은 **추적만** 서술한다. 초기화는 어느 라벨에도 들어가지 않는다.
