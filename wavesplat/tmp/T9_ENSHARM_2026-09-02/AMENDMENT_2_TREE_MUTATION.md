# `T9` 사후 공시 2 — ⛔**나는 배치가 도는 동안 작업트리를 네 번 바꿨다**

> 이 문서는 **판정도 계수도 바꾸지 않는다.** 무슨 일이 있었는지, 그리고 그것이
> 무엇을 무효화하고 무엇을 무효화하지 **않는지**를 자료로 적는다.

---

## 1. 무슨 일이 있었나

`run_t9.py` 가 **돌고 있는 동안**, 나는 다른 일(감사 도구 래칫이 `35 != 36` 으로
실패한 원인 추적) 때문에 저장소 루트에서 다음을 **네 번** 돌렸다:

```
git stash -q ; git checkout -q <옛 커밋> -- . ; git checkout -q HEAD -- . ; git stash pop -q
```

⛔`results_t9.jsonl` 은 **추적되는 파일**이다. 따라서 `git stash` 가 그것을 되돌렸고,
러너는 그 파일을 `open(out, 'a')` 로 **열어 둔 채** 쓰고 있었다.

## 2. 무엇이 실제로 손상됐나 — 자료로

| 검사 | 결과 |
|---|---|
| 행 수 | **367 / 384** (17행 부족) |

⟹ **부족분은 「구멍」이 아니라 「꼬리」다**(순서상 마지막 에피소드들). 중간 손실의

★**가장 중요한 한 줄**: ***`code_md5` 가 367행 전부에서 동일하다*** — 즉 내가 트리를
휘저은 동안에도 **판정에 들어가는 코드는 한 비트도 움직이지 않았다.** 이 저장소가
`S13`·`S13b` 에서 *"`git_head` 만으로는 더러운 트리를 못 잡는다"* 는 대가를 치르고
도입한 바로 그 열이, 오늘 **자기 값을 했다.**

## 3. 처분 — ⛔게이트를 고치지 않는다

`G-5`(행 완비)가 **정확히 발화했고** 배치는 `BLOCKED` 로 나왔다. 라벨은 나오지 않았다.

- ⛔`G-5` 를 완화하지 않는다. ⛔367행으로 분석하지 않는다.
- ✅`run_t9.py` 는 **재개 가능**하다(`done` 집합으로 완료 키를 건너뛴다) ⟹ 부족한 17행을
  **같은 코드로** 채우고 분석을 다시 돌린다.
- ✅재개분의 `code_md5` 가 앞의 367행과 같은지 **분석 전에 확인**한다(같지 않으면 전량 재실행).

## 4. ★교훈 (원장으로 올린다)

***배치가 도는 동안 작업트리를 바꾸지 마라.*** `git stash`·`git checkout -- .` 는
**추적되는 결과 파일을 되돌린다**. 러너가 그 파일을 열어 둔 채 쓰고 있으면
쓰기가 사라진 inode 로 갈 수 있다.

⚠그리고 이 사고는 **다른 방벽이 실패한 자리에서** 났다 — 감사 래칫의 기준선이
손으로 잘못 적혀 있었고(`35`, 실측은 언제나 `36`), 그것을 추적하느라 트리를 휘저었다.
★***방벽의 오탐이 사람을 위험한 행동으로 밀어낸다.***
