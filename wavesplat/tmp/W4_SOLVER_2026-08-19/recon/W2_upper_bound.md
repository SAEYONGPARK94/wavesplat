## 4. 처방 3개 — 이 코드베이스의 언어로

### 4.1 post-lasso 재적합

**이미 구현돼 있다.** `sequential_update.py:1259 amplitude_refit()` 이
`run_w3.run_cvx` 와 **같은 선형계**를 푼다 `[M]`:

```
theta_i = kx_i·x + ky_i·y - omega_i·t                 (:1311-1313)  # phi 없음
A       = [cos θ_1, sin θ_1, cos θ_2, sin θ_2, ...]   (:1317-1319)  # (M, 2N) 교차배치
coeffs  = lstsq(A, z)                                 (:1330)
a,b     = coeffs[0::2], coeffs[1::2]                  (:1332-1333)
w       = sqrt(a^2 + b^2)                             (:1334)
phi     = arctan2(b, a)                               (:1335)   ← ⛔버그
```
`run_cvx:424-425` 는 같은 것을 **블록 배치**(`[cos | sin]`)로 푼다. **수학적으로 동일. 재사용 가능하다.**

#### ⛔★★★ 버그 1건 — `:1335` 의 위상 부호가 뒤집혀 있다 `[M]`

전방모델은 `z = Σ w·cos(θ + φ)` (`spectral_gaussian.py:121-127`) 이므로
`a = w·cosφ`, **`b = −w·sinφ`** ⟹ **`φ = atan2(−b, a)`** 여야 한다.
수치 확인(N=4, M=500, 무잡음, `numpy`):

| 설치식 | 모델 재구성 RMSE |
|---|---|
| `atan2(b, a)` (현재 코드) | **1.372e+00** (신호 스케일과 같은 크기 = 완전 파괴) |
| `atan2(-b, a)` | **9.013e-16** |
| 참고: LS 잔차 `‖Ac − z‖` | 8.662e-16 |

⚠**조용한 실패다**: `:1355` 의 `residual_after` 는 **`A @ coeffs`** 로 계산되므로
설치된 `(w, φ)` 가 틀려도 **완벽한 잔차를 인쇄한다.**

**도달성** `[M]`: `run.py:398` `if cfg.get('amplitude_refit', False)` — **옵트인, 기본 OFF**.
저장소 전체에서 이 키를 켜는 곳은 **0곳**(`grep -rl amplitude_refit` = `run.py` · `optimizer/sequential_update.py` ·
`tests/test_bank_mmse_port.py` · `graphify-out/` 캐시뿐).
⟹ ✅**과거 결과 오염 0건.** ⛔**그러나 지금 이 함수를 그냥 켜면 필드가 파괴된다.**
(참고: `sequential_update.py:1215 _ls_w_update` 는 **호출자 0곳 = 사장 코드**다 `[M]`.)

**지지집합 규칙 `S`**: 현재 코드는 `S = {살아남은 모든 원자}` 다(선택은 `adaptive_n` 의
`prune_threshold=0.10` 이 이미 했다). 진짜 post-lasso 라면 `S = {i : |w_i| > τ}` 를 따로 골라야 하지만,
**PROBE-A 가 `S = 전체` 에서 혼잡 널을 냈으므로 `S` 를 더 좁히는 것은 상한을 낮출 뿐이다** `[A]`.

**난이도·비용**: **부호 수정 1글자 + 플래그 노출 ~4줄.** 런 비용 `lstsq` 1회 = **에피소드당 <0.1 s**.
**⟹ 값은 싸지만, 혼잡 기대효과는 측정된 0% 다.**

### 4.2 VARPRO

**소거 후 목적함수** (`(a,b)` 는 닫힌형으로 제거):
```
K = (kx, ky) ∈ R^{2N}
θ_ij(K) = kx_j·x_i + ky_j·y_i − ω_j(K)·t_i ,  ω_j = sqrt(g·|k_j|·tanh(|k_j|·d))
Φ(K)    = [cos Θ | sin Θ]                                  (M × 2N)
c(K)    = Φ⁺ z          (또는 (ΦᵀΦ + εI)⁻¹ Φᵀ z)
f(K)    = ‖ P⊥(K) z ‖² / M ,   P⊥ = I − Φ Φ⁺
```
**야코비안**은 해석적으로 있다(Golub–Pereyra):
`∂f/∂K_j = −(2/M)·zᵀ P⊥ (∂Φ/∂K_j) Φ⁺z` (Kaufman 근사는 둘째 항을 버린다).
필요한 조각 `[M]`:
```
∂θ_i/∂kx_j = x_i − t_i · (∂ω/∂k)|_{k_j} · (kx_j / |k_j|)
∂ω/∂k = ( g·tanh(k d) + g·k·d·sech²(k d) ) / (2ω)          # spectral_gaussian.py:100-101 의 도함수
∂cos θ_j/∂kx_j = −sin θ_j · ∂θ_j/∂kx_j ,  ∂sin θ_j/∂kx_j = +cos θ_j · ∂θ_j/∂kx_j
```
⟹ ★**유한차분은 필요 없다.** 그리고 **손으로 짤 필요도 없다** — 전 경로가 미분가능한 torch 이므로
`torch.linalg.solve(ΦᵀΦ + εI, Φᵀz)` 로 짜면 autograd 가 정확히 이 야코비안을 준다.
PROBE-B 가 그렇게 했다(`probe_varpro.py:_fc`). ⚠`torch.linalg.lstsq` 는 autograd 지원이 제한적이므로
**정규방정식 + ridge** 를 쓸 것.

⚠**중요**: `use_dispersion=True` 라 ω 가 k 에 묶여 있고, `run_cvx` 도 그렇게 한다 `[M]`
⟹ VARPRO 는 자유 파라미터가 **2N 개**(N개 아님)이고 ω 항이 시간축 정보를 k 로 되돌린다.

**난이도**: 새 함수 ~60줄 + 배치 하네스에서 `SequentialUpdater.initialize` 를 감싸는 몽키패치 ~40줄
= **~100줄, 패키지 무수정**(W1 이 삽입 지점을 `initialize` 직후로 확정했다).
**런 비용**: 400스텝 = **에피소드당 +2.3 s**(실측, `M≈8080`, `N≈20`, float64, 8스레드) `[P]`
⟹ 출하 런 21 s 대비 **+11%**.

### 4.3 Sliding Frank–Wolfe

**원자 추가 규칙** (쌍대 인증서 = 잔차와의 최대 상관):
```
r ← z − Φ(K) c                         # 현재 잔차
η(k) = sqrt( ⟨r, cos θ_k⟩² + ⟨r, sin θ_k⟩² ) / ‖(cos,sin)‖   # 복소 진폭 모듈러스
k*   = argmax_k η(k)                   # 조 그리드 argmax → 연속 상승(Nelder–Mead 또는 위 §4.2 기울기)
K ← K ∪ {k*}
```
**슬라이딩 단계**: 원자를 추가할 때마다 **모든** `(k_i, a_i, b_i)` 를 함께 재최적화
= **§4.2 VARPRO 를 커지는 사전 위에서 반복**하는 것. 정지규칙은 `max η ≤ λ` (BLASSO 쌍대 조건).

**성장 분기와 충돌하는가** — **하지 않는다** `[M]`:
`_initialize_learned` 가 코스투파인 staging 을 우회하므로 `coarse_to_fine._beamform_residuals` 는
배포 혼잡에서 실행되지 않고, W3 의 W-3 스모크가 오라클 셀에서도 `lp_calls=0 · add_calls=0` 를
확인했다(`NOTES.md`). ⟹ **SFW 는 죽은 분기를 건드리는 게 아니라 `initialize` 의 출력을 대체해야 한다.**
⚠**이것이 축이 죽는 5번째 자리**이므로 **원자 카운터로 런 0회 개입 확인 필수**(W3 G-4 방식).

**난이도**: ~250줄(그리드 상관 + 연속 상승 + 슬라이딩 루프 + 카운터).
**런 비용**: 원자당 (상관 스윕 `M×|grid|`; 200×200 격자면 8080×40000 ≈ 3.2e8 → ~0.3 s)
+ 슬라이딩 VARPRO. N≈22 이면 **에피소드당 15–60 s** `[A]` ⟹ 출하 대비 **×1.7–3.9**.

⚠**초해상 조건**: SFW/BLASSO 의 정확복원 보증은 원자 분리 ≳ 2 Rayleigh 를 요구한다.
§3.4 가 잰 혼잡 분리는 **1.29 Rayleigh**(최소 0.22) ⟹ **보증 밖**이다 `[M/A]`.
⟹ **SFW 를 "이론적으로 보장된 처방" 으로 팔면 안 된다.** 희소(5.02)는 보증 안이다.

## 6. 실패 예측 — 각 처방이 실패한다면 어떤 모양인가

### 6.1 post-lasso — ⛔**이미 실패했다. 그리고 FITPHI 실패의 재탕이 맞다.**

- 예측된 실패 형태: **"완전히 개입해도 안 산다"**. `SHIP-FITPHI`(개입 0/32) →
  `KONLY-FITPHI`(개입 96/96, 20/32 FAIL) → **PROBE-A**(정확한 전역 닫힌형, 6/16 · +0.3%).
  세 번 모두 **k 고정 · `(w,φ)` 만 고침**이다.
- ★**"재탕이 아닌 이유" 를 나는 못 댄다.** 유일하게 남는 변호는 *"S4/S5 는 추적기 OFF 라
  배포 팔과 다르다"* 인데, 그건 **W3 의 `SHIP-FITPHI`(추적기 ON, 배포 팔)가 이미 널로 막아 뒀다**.
  ⟹ **이 축은 닫는다. `amplitude_refit` 의 부호 버그는 그것과 무관하게 고친다.**

### 6.2 VARPRO — 세 가지로 실패할 수 있다

1. ⚠**"창은 맞추는데 필드는 안 맞는다"** — §3.4 에서 이미 부분적으로 보였다
   (`ORA-K-NT`+VP 는 창 잔차 ×1.08 인데 필드 ×37).
   **온라인 팔에서 이 모양이 더 세지면 판정은 "관측 지지 밖 식별 불가"(E-C 의 이름)로 돌아가고,
   그건 솔버 축이 아니라 개구 축이다.** ⟹ 게이트: **창 잔차와 필드 nRMSE 를 같은 행에 기록**.
2. ⚠**추적기와 싸운다** — VARPRO 는 `(w,φ)` 를 `(a,b)` 로 다시 쓰고 k 를 옮긴다. 그 뒤
   `tracking_mode='w_phi'` 가 10스텝/프레임으로 `(w,φ)` 를 다시 흔든다.
   PROBE-B 는 **추적기 OFF 표본**에서 잰 값이다 ⟹ **온라인에서 이득이 부분적으로 씻길 수 있다.**
   ⟹ 게이트: `SHIP+VP` 와 `SHIP+VP(tracking_lr=0)` 를 **둘 다** 넣을 것.
3. ⚠**`learned` 라우트 밖에서는 개입이 없다** — 배포 혼잡의 86–90% 만 `learned` 다(W1 측정).
   나머지 행에서 개입 0 이면 **묽어진 평균**이 나온다. ⟹ 원자 카운터 필수.
4. ⚠**시드 1개** — 저장소가 이미 혼잡 CV 14.4%·18/64 부호 반전을 쟀다(S13b).
   PRIMARY 를 시드 1개로 잡으면 S13 의 실수를 반복한다. ⟹ 스모크는 1시드, **확증은 median-of-3**.
5. ⛔**"스텝을 더 주면 된다" 는 이미 반증됐다** — §3.5 가 400→4000 에서 창 잔차 불변·nRMSE 진동을
   실측했다. ⟹ **스텝수 스윕을 W4 의 축으로 삼지 말 것**(λ 스윕이 W3 에서 죽은 것과 같은 종류의 낭비다).

### 6.3 SFW — 두 가지

1. ⚠**분리 조건 위반**(1.29 Rayleigh) ⟹ 쌍대 인증서가 **한 주엽 안에 두 원자를 얹는다**.
   이 실패 모드는 저장소가 이미 다른 이름으로 알고 있다 — `learned_dedup_dk=0.03` 이
   측정된 분해능(0.042–0.074)보다 작다는 그 지적이다. ⟹ **`merge_atoms` 를 동반 팔로 붙일 것.**
2. ⚠**죽은 분기 재방문** — `_beamform_residuals` 를 건드리면 **네 번 죽은 자리에 다섯 번째**가 된다.
   ⟹ **`initialize` 출력 대체 + 원자 카운터**로만 설계할 것.
