# 원격 백업 — **성공** (2026-08-24 02:29)

## 문제
`git push origin learn-boundwave-retrain` 이 **50분 무응답 후 타임아웃**.

## 진단 (측정)
```
미푸시 범위 14c8861..HEAD  =  307 커밋 · 12,508 객체 · blob 합계 738.3 MB
  · 08-23 이전분(14c8861..1d77211)  = 728.1 MB   ← 막는 것
  · 오늘분(1d77211..HEAD)           =  10.2 MB   ← 막지 않는다
최대 blob: venv_fowd/…/libopenblas64.so 33.5 MB · libscipy_openblas 23.7 MB ·
           results/gifs/*.gif 9–14 MB 다수 · ref_paper/*.pdf 13.8 MB
```
⟹ ★**막는 것은 오늘 밤 결과물이 아니라 08-21 에 추적 해제했지만 *이력에 남은* 바이너리다.**
(`bed9c75` 가 `venv_fowd` 465 MB + `results/gifs` 293 MB 를 추적 해제했으나 이력은 그대로다.)

## 해결
기존 클린 미러 `backup/records-clean-2026-08-21`(`b1fc6cb`) 위에
`bed9c75..HEAD` **162 커밋을 cherry-pick** ⟹ **충돌 0건**.
(오늘 커밋들이 벗겨진 경로 `wavesplat/data*`·`gifs`·`venv_fowd` 를 **하나도 건드리지 않기** 때문.)

**검증**: 새 미러 ↔ 실제 브랜치의
`.py`/`.md`/`.json`/`.jsonl`/`.tex`/`.yaml`/`.txt`/`.bib` 차이 = ★**0건**.
다른 것은 `.h5`·gif·PDF 등 **재생산 가능한 바이너리뿐**이다.

**푸시**: `backup/records-clean-2026-08-24` → **16.2 MB, 성공** (`b9c2cef`).

## ⚠단서
- **미러는 해시가 다르다** ⟹ 연구 기록이 인용하는 `git_head` 는 **여전히 로컬 전용**이다.
  (08-21 에도 같은 조건이었고 태그 `local-full-2026-08-21` 로 남겼다.)
- 원본 브랜치를 정말 올리려면 **이력에서 바이너리를 벗겨야** 한다
  (`git filter-repo` 필요 — 이 기계에 **없다**).

## ★처방
***재생산 가능한 것을 커밋하지 마라.*** 한 번 들어가면 추적 해제로는 안 빠지고,
그때부터 **모든 백업이 그 무게를 진다.** 오늘 밤 10 MB 를 올리는 데 728 MB 가 걸림돌이었다.
