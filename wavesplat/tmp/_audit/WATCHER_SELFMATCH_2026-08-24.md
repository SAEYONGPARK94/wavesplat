# 감시 자기매칭 — **이미 기록된 결함을 내가 그대로 반복했다** (2026-08-24 01:33)

## 무슨 일
`B-12` 생성이 끝나면 추정을 자동으로 잇도록 감시를 걸었다:
```bash
nohup bash -c 'while pgrep -f "python3 gen_b12.py" >/dev/null; do sleep 60; done; ... python3 run_b12.py'
```
⛔**`pgrep -f` 는 전체 명령줄을 본다.** 이 `bash -c` 자신의 명령줄에 문자열
`python3 gen_b12.py` 가 들어 있으므로 **감시가 자기 자신을 발견한다** ⟹ 루프가 **영원히** 안 끝난다.

생성은 **01:33:42 에 정상 종료**했는데 체인은 발화하지 않았다.
(⚠운이 좋았다 — 내가 **01:33 에 직접 확인**해서 손실이 사실상 0이었다.
 그러지 않았다면 아침까지 놀았을 것이다.)

## ★이것이 처음이 아니다
`MEMORY.md` 2026-08-16 `W3` 항목 축자: ***"⛔내 운영 실수 2건(감시 자기매칭 **8h 손실** · 러너 인자 공백)"***.
⟹ ***같은 결함을, 원장에 적어 놓고, 8일 뒤에 그대로 반복했다.***
**적어 두는 것만으로는 반복을 막지 못한다.**

## ★처방 (코드로)
1. **PID 를 잡아라, 이름을 잡지 마라.**
   ```bash
   python3 gen_b12.py & GEN=$!; wait $GEN; python3 run_b12.py
   ```
2. 이름으로 봐야 한다면 **자기 자신을 제외**하라: `pgrep -f pat | grep -v ^$$`
   또는 `pgrep -x python3` 로 **실행 파일 이름**을 잡고 `/proc/<pid>/cmdline` 을 확인하라
   (이 문서를 쓰게 만든 진단이 바로 그 방법이었다).
3. ★**가장 좋은 것은 감시를 안 만드는 것**이다 — 하네스의 추적되는 백그라운드 실행을 쓰면
   종료 시 **알림이 온다**. (08-22 에 `nohup &` 로 떼어 돌려 3시간을 놓친 것도 같은 뿌리다.)

## ⚠부수 사고 하나 더 (같은 5분 안에)
정리하려고 `pkill -f "while pgrep ..."` 을 돌렸더니 **하네스가 추적하던 내 대기 작업까지 죽였다**
(그것의 명령줄에도 같은 문자열이 있었다). ⟹ **패턴 kill 은 의도한 것보다 넓게 잡는다.**
★처방: **PID 로 죽여라.**
